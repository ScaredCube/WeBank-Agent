# T-304 模拟订阅 / 代扣接口

状态：后端已实现并通过测试，前端按人工要求暂不接线；订阅、扣费日期和识别结果均为模拟数据，不对接真实代扣或商户系统。

## 1. 接口分层

银行数据只读接口（供前端负一屏和服务层封装使用，不注册为 Agent Tool）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/bank/subscriptions` | 当前用户模拟订阅：商户、金额、周期、下次扣费日期、剩余天数、续费提醒、状态、`can_cancel` |
| GET | `/api/bank/subscriptions/candidates` | 从最近模拟消费流水中识别可能的重复订阅，仅返回候选，不落库 |

Agent 业务操作接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/subscriptions/{subscription_id}/cancel/prepare` | 创建黄色取消动作，首次返回一次性确认令牌 |
| POST | `/api/subscriptions/cancel/{action_id}/execute` | 用户确认后执行取消；尚未确认时拒绝 |

所有接口需要 Bearer 登录令牌，受用户级锁定与限流约束；成功响应带 `Cache-Control: no-store`。只读接口不返回 `subscription_token` 或任何一次性令牌。

## 2. Tool

绿色只读：

- `get_subscriptions`：返回订阅字段和可取消订阅的 `subscription_token`。
- `detect_subscriptions`：返回可能的重复订阅候选，不自动创建订阅、不自动取消。

黄色准备：

- `prepare_cancel_subscription`：参数 `subscription_token`；只创建待确认动作并返回 `action_required`，不直接取消。

AgentLoop 将 `prepare_cancel_subscription` 与转账、理财准备一样处理：令牌只交给客户端，不写入模型消息、会话历史或日志。

## 3. 取消流程

1. Agent 或前端调用准备接口，服务端创建 `PendingAction`（黄色）和 `SubscriptionCancelRequest`。
2. 客户端调用 `POST /api/actions/{action_id}/confirm` 提交一次性令牌。
3. 客户端调用 `POST /api/subscriptions/cancel/{action_id}/execute`；服务端再次检查动作归属、黄色等级、已确认状态和有效期，然后把订阅状态改为 `cancelled`。
4. 准备、确认都不代表已取消；只有执行成功才改变订阅状态，结果以执行接口返回为准。

取消订阅是固定的黄色确认操作，**不做夜间升级为红色**：它是非资金类停止操作，不扣款、不转移资金。该口径需在安全自评中说明。

## 4. 订阅识别

`detect_subscriptions` 和 `/api/bank/subscriptions/candidates` 扫描最近 6 个月的模拟支出流水：

- 排除类别 `模拟转账`、`理财申购`、`理财赎回`；
- 同一商户 + 同一金额至少出现 2 次，且分布在不同自然月；
- 返回商户、金额、次数、最近一次时间和建议周期（演示固定 `monthly`）；
- 最多返回 10 条。

识别是启发式提示，不是扣费确认，也不代表已发现真实订阅；用户仍需确认后调用取消流程。

## 5. 续费提醒

`/api/bank/subscriptions` 和 `get_subscriptions` 返回：

- `next_charge_date`：下次扣费日期；
- `days_until_charge`：按北京时间计算的剩余天数；
- `renewal_soon`：生效中且 0–7 天内扣费时为 `true`；
- `can_cancel`：仅生效中订阅为 `true`。

## 6. 数据与种子

新增表：

- `Subscription`：`id`、`user_id`、商户、金额（分）、周期、下次扣费日期、状态、创建 / 更新时间。
- `SubscriptionCancelRequest`：`id`、`user_id`、`subscription_id`、`action_id`（唯一）、状态。

启动时为演示用户幂等创建 2 个模拟订阅，不改变账户余额或流水。

## 7. 审计

新增事件：`subscription_cancel_prepared`、`subscription_cancel_prepare_denied`、`subscription_cancel_prepare_failed`、`subscription_cancelled`、`subscription_cancel_retried`、`subscription_cancel_denied`、`subscription_cancel_failed`。

新增 Tool 名：`get_subscriptions`、`detect_subscriptions`、`prepare_cancel_subscription`、`subscription_cancel`。

执行成功、订阅状态变更和审计在同一事务内；审计失败时回滚，不报告成功。

## 9. 限制

- 订阅和识别结果均为模拟数据；没有真实代扣、账单或商户接口。
- 识别是启发式规则，可能误报或漏报，不构成扣费确认。
- 准备接口可传 `{"idempotency_key":"client-operation-0001"}`；同用户同键同订阅返回原动作，不重新返回确认令牌；同键换订阅拒绝。不传编号保持旧行为，可能生成多个申请，只有第一个执行成功。
- 执行重查准备时订阅引用；吊销、失效或缺少绑定均拒绝。升级前未完成申请须重新准备。新增准备回执/绑定表与事务入口见 `T-206事务与幂等说明.md`。
- 仅支持 SQLite；前端未接线；跨 HTTP 聊天去重和统一执行调度器未实现。
