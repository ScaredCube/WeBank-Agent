# 前端接口需求与协作边界

状态：前端协作需求与现状说明。功能分支已随 PR #3 合并到 `main`（`007d7fb`）；以下“当前基线”描述合并后能力，其他“建议／待确认”部分仍不是已实现接口。项目中的账户与操作均为模拟。

## 当前基线

- 2026-11-01 合并后：`/api/bank/dashboard` 提供账户、联系人、持仓、风险测评与生成时间；账户含稳定 ID、余额、币种和状态，联系人及持仓各有 ID。它们是只读展示快照，不构成交易授权。`/api/cards` 新增 `account_id`，用于资产卡面与挂失入口映射。
- 正式 `/chat` 已支持账户／银行卡／联系人 typed references（`ChatRequest.references`），服务端重新校验归属与状态后生成 `DataToken` 并绑定工具调用；前端本地引用胶囊只有服务端校验后才具有只读上下文意义，资金操作仍必须独立确认。
- **2026-11-01 前置意图（已实现，提示词方案）**：`ChatRequest.intent` 接受 `{action, source:{kind,id}, target:{kind,id}}`。前端不传标签、token、金额；服务端 `intent_service` 校验归属与状态，生成 token 化中文提示词（例如 `【前置意图】用<CARD_...>给<CONTACT_...>（张三）转账`）并放在当轮用户原文之前注入模型。用户消息顶部持久化用户可见的胶囊行，历史回读后在气泡上方显示；token 正文不写入历史。模型金额必须与用户原文一致；来源/目标 token 由服务端覆盖，模型不能替换。六种动作均已有模拟业务链。
- **新增事件**：`operation_result`（当前仅 `internal_transfer`）只由服务端绿色内部转账 Tool 产生，用于当前页面结果卡；尚未承诺通过 `MessageResult` 刷新恢复。
- 用户输入按原文展示、保存并送模型，前端不对用户输入的卡号／手机号做遮罩；工具结果与工具参数仍使用脱敏字段或令牌，查询 Tool 不向模型返回真实卡号。
- 模拟理财和订阅的只读及操作接口已加入；前端已适配 Agent 触发的理财申购／赎回和订阅取消动作。挂失与订阅准备支持可选幂等键，但重复准备不重新发放确认凭证。
- 对话请求支持文本、`request_id` 和 SSE；`ChatSubmission` 对同一客户端请求去重，历史消息可通过 `MessageResult` 回读加密的可信账单／银行卡结果；通用界面描述协议仍未开放，`bill_result` / `card_result` 之外的卡片没有稳定历史 Schema。
- 银行卡、月度账单、审计及动作确认、模拟验证、转账、挂失、理财和订阅执行已有接口，具体字段以各专项接口文档及代码为准。月度账单不传账户 ID 时仅在恰有一个可用账户时自动选择；多账户需要指定账户。
- 卡片列表不提供账户 ID；账户列表有账户 ID 与余额，但未提供通用卡片 ID 映射。服务端已通过卡到账户关联校验所选卡，前端仍不能以卡片 ID 推断账户 ID，不能凭模型文本补造余额。
- 动作确认凭证只在准备或事件返回时提供，不能从动作详情恢复。确认或验证不代表业务已经执行；结果以执行接口及可用的状态查询为准。同一 `request_id` 重试若已有待确认动作，只返回 `action_warning`，不会重新下发令牌。

## P0：启用对应能力前需要确认

### 账户与资产

场景：资产工作面展示账户、卡片及余额，并将用户选择的账户用于后续操作。账户列表与余额已有只读接口，仍需核实多卡映射、数据时效及用于动作时的引用语义。

建议提供稳定账户引用、卡片与账户关联、脱敏名称、状态、币种、整数金额单位及数据时间。服务端校验用户归属，区分空列表、无权限、数据暂不可用。验收包含跨用户引用拒绝、冻结账户与卡片状态分别展示，以及余额时间和单位一致。

### 前置意图

场景：用户选择来源和目标后，继续与 Agent 交互。**当前已实现**：前端只提交动作与实体 ID；服务端校验归属、状态和碰撞矩阵，生成 token 化前置提示词，拼在当轮用户原文之前注入模型，同时覆盖金额、来源、目标，模型不能替换。用户消息顶部持久化可见胶囊行，气泡上方展示；token 正文不写入历史。胶囊在发送、取消、切换会话后清空；未定义组合不生成胶囊。**仍需确认**：跨设备恢复、提示词版本兼容和真实模型下的六动作完整人工验收；本地胶囊本身不是授权凭证。

### 结构化工具结果与 Intelligent UI

场景：Agent 将工具结果呈现为可交互的界面。**当前已实现**：服务端只接受成功 Tool 产生的 `bill_result` / `card_result`，Pydantic 校验后加密保存为 `MessageResult`，历史回读时解密并再次校验；模型文本不能制造这些事件。**仍需确认**：通用版本化界面描述、组件白名单、数据绑定、允许交互和未知版本降级。前端仅渲染受控组件，确认和执行仍使用固定业务流程。

### P0 联调讨论字段清单

以下是需要协商的语义，不是现有字段名或已经确定的接口设计。

| 能力 | 希望后端明确 | 前端处理 | 联调验收 |
| --- | --- | --- | --- |
| 资产引用 | 账户、银行卡、联系人和持仓各自的稳定引用及其所属用户；卡与账户是否存在一对多关系 | 分别保存实体类型与引用，不把卡片 ID 当作账户 ID；数据缺失时显示不可用 | 不同实体同号不混淆；其他用户的引用被拒绝；失效对象显示可理解状态 |
| 余额和时间 | 余额对应账户、币种、整数单位、查询时间与不可用原因 | 使用服务端数值与时间；缺少任一必要语义时不显示可信余额 | 零余额、查询超时、多币种和冻结状态都可区分 |
| 组合意图 | 来源、目标、动作类型；服务端生成的 token 化提示词；拒绝原因 | 本地胶囊表达用户选择；发送时只传实体 ID。服务端校验归属和对象状态，覆盖来源/目标/金额 | 伪造、跨用户、未定义组合、金额不一致均拒绝；用户消息顶部保存可见胶囊行，token 正文不写入历史 |
| 可信工具数据 | 工具结果标识、归属会话／消息、数据时间、数据来源及错误语义 | 区分数据和布局建议；不能由模型单方面提供业务事实 | 来源缺失或校验失败不展示为已核实数据；错误不使整段对话消失 |
| 界面描述 | 版本、可用组件、数据绑定方式、允许的交互标识及兼容策略 | 只渲染白名单组件与属性；未知版本和组件局部降级，动作进入固定流程 | 恶意脚本、外部地址、未知组件和不兼容版本均不执行；只读卡片仍可保存为安全快照 |

未有上述契约时，合成预览仅用于验证交互，服务模式不会将预览对象或模拟结果发送到后端。

## P1：恢复与完整性

- **确认或验证后撤销**：目前取消动作只接受待确认状态；黄色动作已确认或红色动作已验证后，关闭界面不会撤销服务端动作。需要团队明确是否支持撤销已确认但尚未执行的动作、允许撤销的状态与时限、并发执行时的最终结果，以及审计语义。前端目前不能将关闭弹窗展示为撤销成功。
- **消息发送关联与结果核实**：**已实现基础协议**：客户端每次发送带 `request_id`，服务端 `ChatSubmission` 以 `(user_id, request_id)` 唯一约束去重，记录处理中／完成／待确认／中断／失败状态；`GET /api/chat/conversations/{id}/requests/{request_id}` 只读核对结果，不返回确认令牌。**仍需明确**：多端同文、跨设备恢复、长期状态保留和冲突语义。
- **操作恢复与幂等**：**已实现部分**：挂失与订阅准备支持幂等键；聊天请求 `request_id` 去重；同标签页 `sessionStorage` 保存非机密恢复线索，刷新后只读核对状态；有已完成、待确认、处理中／中断／失败分支。**仍缺失**：确认令牌丢失后无法恢复；动作事件损坏或首次响应未到达时，没有按幂等键查询待处理动作的通用只读入口；已确认／已验证动作的撤销语义未定义。
- **结构化历史**：**已实现账单／银行卡**：`MessageResult` 加密保存可信结果，历史回读解密并做 Schema 校验，不返回确认凭证、不重新开放执行，按用户和会话隔离。**仍需约定**：通用卡片标识、版本兼容、未知组件降级和更多卡片类型。
- **联系人与持仓**：只读字段、实体 ID 与状态已提供；单项更新时间和用于前置意图的身份语义仍需明确。验收覆盖空数据、失效实体和跨用户访问。

## P2：体验增强

- **任务控制**：定义任务标识、服务端停止语义、状态查询、事件顺序与可重放范围。浏览器停止接收不等于服务端停止执行。
- **收藏同步与刷新**：定义用户隔离、保存、删除、版本迁移、来源追溯及显式刷新。刷新需要重新鉴权并获取新数据，不静默覆盖历史快照。
- **快照敏感字段语义**：前端当前只允许已知卡片结构，并按规则遮盖部分号码与引用，不能自动识别所有姓名和自由文本中的敏感信息。建议后端为可保存的字段提供数据分类、脱敏值和保存策略；验收覆盖姓名、联系方式、自由文本和未知字段，不把前端正则替换当作完整脱敏。
- **审计筛选与分页**：补充会话、动作过滤及分页完整性语义。当前前端只能对已加载记录本地筛选，不应称其为全量筛选。
- **长会话历史分页**：**已实现** `GET /api/chat/conversations/{id}/messages?limit=&before_id=` 的 keyset 分页，前端默认最近 50 条并支持向前加载、阅读锚点保持；助手结果快照按 400 个 ID 分批查询，避免 N+1。**仍存在**：无参数旧调用继续返回完整历史（兼容但无界），会话列表仍一次返回全部，收藏来源定位最多回溯 20 页；需要容量目标和旧接口废弃窗口。

## 前端独立推进原则

后端缺口不阻塞页面结构、状态、受控组件和合成数据下的交互验证。真实接口失败时不得自动切换为样例数据；本地静态收藏不包含凭证或可重放的业务操作。真实接口、隔离样例和真实模型验证应分别记录结果。
