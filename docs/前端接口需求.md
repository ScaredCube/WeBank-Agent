# 前端接口需求与协作边界

状态：前端方案提议，待前后端共同确认；不表示以下新增接口或能力已经实现。项目中的账户与操作均为模拟。

## 当前基线

- 2026-10-29 同步至 `e114798c`：`/api/bank/dashboard` 提供账户、联系人、持仓、风险测评与生成时间；账户含稳定 ID、余额、币种和状态，联系人及持仓各有 ID。它们是只读展示快照，不构成交易授权。各字段和多卡映射、更新时效仍需联调确认。
- 模拟理财和订阅的只读及操作接口已加入；本地前端已适配 Agent 触发的理财申购／赎回和订阅取消动作，尚未真实联调。挂失与订阅准备支持可选幂等键，但重复准备不重新发放确认凭证，响应丢失的恢复仍需按服务端语义处理。
- 对话请求支持文本和 SSE；历史消息为文本，尚不能回读结构化工具结果或界面描述。现有事件没有断点续传保证。
- 银行卡、月度账单、审计及动作确认、模拟验证、转账和挂失执行已有接口，具体字段以各专项接口文档及代码为准。月度账单不传账户 ID 时仅在恰有一个可用账户时自动选择；多账户需要指定账户。
- 卡片列表本身不提供账户 ID 或余额；新的账户列表有账户 ID 与余额，但未提供卡片 ID 映射。前端不能以卡片 ID 推断账户 ID，不能凭模型文本补造余额。
- 动作确认凭证只在准备或事件返回时提供，不能从动作详情恢复。确认或验证不代表业务已经执行；结果以执行接口及可用的状态查询为准。

## P0：启用对应能力前需要确认

### 账户与资产

场景：资产工作面展示账户、卡片及余额，并将用户选择的账户用于后续操作。账户列表与余额已有只读接口，仍需核实多卡映射、数据时效及用于动作时的引用语义。

建议提供稳定账户引用、卡片与账户关联、脱敏名称、状态、币种、整数金额单位及数据时间。服务端校验用户归属，区分空列表、无权限、数据暂不可用。验收包含跨用户引用拒绝、冻结账户与卡片状态分别展示，以及余额时间和单位一致。

### 前置意图

场景：用户选择来源和目标后，继续与 Agent 交互。建议约定动作类型、来源与目标实体引用、会话关联，以及采纳或拒绝结果。服务端必须校验归属与可用性，并约束工具参数与已确认意图一致。验收包括伪造引用、对象变更、过期和取消；未实现时前端不能将本地胶囊当作服务端已绑定意图。

### 结构化工具结果与 Intelligent UI

场景：Agent 将工具结果呈现为可交互的界面。建议共同定义版本、消息及工具关联、数据来源、查询时间、组件描述、允许的交互和错误语义。可信业务数据应由服务端工具结果提供；模型生成的布局建议不能自行证明数字真实，也不能自行证明它与某条会话或消息的关联。来源引用由具备上下文的服务端或可信适配器提供，服务端校验用户、会话与消息之间的归属关系。前端仅渲染受控组件，确认和执行仍使用固定业务流程。验收包括未知版本、异常组件、缺失数据、伪造来源和无权限交互的安全降级。

### P0 联调讨论字段清单

以下是需要协商的语义，不是现有字段名或已经确定的接口设计。

| 能力 | 希望后端明确 | 前端处理 | 联调验收 |
| --- | --- | --- | --- |
| 资产引用 | 账户、银行卡、联系人和持仓各自的稳定引用及其所属用户；卡与账户是否存在一对多关系 | 分别保存实体类型与引用，不把卡片 ID 当作账户 ID；数据缺失时显示不可用 | 不同实体同号不混淆；其他用户的引用被拒绝；失效对象显示可理解状态 |
| 余额和时间 | 余额对应账户、币种、整数单位、查询时间与不可用原因 | 使用服务端数值与时间；缺少任一必要语义时不显示可信余额 | 零余额、查询超时、多币种和冻结状态都可区分 |
| 组合意图 | 来源、目标、动作类型、所属会话、失效方式，以及采纳或拒绝的明确结果 | 本地胶囊仅表达用户选择，直到服务端确认绑定才作为有效上下文；失败保留并允许移除 | 服务端校验归属和对象状态；伪造、过期、对象被替换均拒绝，并返回可展示的原因 |
| 可信工具数据 | 工具结果标识、归属会话／消息、数据时间、数据来源及错误语义 | 区分数据和布局建议；不能由模型单方面提供业务事实 | 来源缺失或校验失败不展示为已核实数据；错误不使整段对话消失 |
| 界面描述 | 版本、可用组件、数据绑定方式、允许的交互标识及兼容策略 | 只渲染白名单组件与属性；未知版本和组件局部降级，动作进入固定流程 | 恶意脚本、外部地址、未知组件和不兼容版本均不执行；只读卡片仍可保存为安全快照 |

未有上述契约时，合成预览仅用于验证交互，服务模式不会将预览对象或模拟结果发送到后端。

## P1：恢复与完整性

- **确认或验证后撤销**：目前取消动作只接受待确认状态；黄色动作已确认或红色动作已验证后，关闭界面不会撤销服务端动作。需要团队明确是否支持撤销已确认但尚未执行的动作、允许撤销的状态与时限、并发执行时的最终结果，以及审计语义。前端目前不能将关闭弹窗展示为撤销成功。
- **消息发送关联与结果核实**：当前客户端只能按历史文本和时间间接判断发送结果；其他设备可能发送同文，因此无法可靠确认某次请求是否已写入。建议协商由客户端为每次发送提供稳定标识，服务端在消息写入、响应及历史回读中关联该标识，并明确用户与会话归属、重复请求和冲突语义。验收覆盖写入成功但响应丢失、多端同文、重试和跨用户伪造。前端在契约实现前保留原草稿并提示结果未知，不据同文判定发送成功。
- **操作恢复与幂等**：明确准备和执行请求的重试规则、结果查询、确认凭证丢失与过期后的处理。动作事件损坏时，前端无法获得可靠动作标识或恢复凭证，需要服务端提供按用户和会话核实待处理动作的安全方式。2026-10-29 起，银行卡挂失前端会提交幂等键，并在当前 Chat 内存中保留以支持用户主动同键核对；重复准备只能找回动作 ID，不能取回确认凭证。页面刷新会丢失客户端键；若首次响应连动作 ID 也未到达，当前 API 没有按幂等键查询动作的只读入口。建议后端提供按用户与业务实体核实待处理动作的安全查询方式，并明确过期后的新申请规则。验收覆盖请求成功但响应丢失、事件格式损坏、重复点击、动作已完成和状态未知。
- **结构化历史**：约定卡片、工具结果的稳定标识、版本及关联消息的回读方式。历史回读不返回确认凭证，也不重新开放执行；验收覆盖旧版本、缺失组件和用户隔离。
- **联系人与持仓**：只读字段、实体 ID 与状态已提供；单项更新时间和用于前置意图的身份语义仍需明确。验收覆盖空数据、失效实体和跨用户访问。

## P2：体验增强

- **任务控制**：定义任务标识、服务端停止语义、状态查询、事件顺序与可重放范围。浏览器停止接收不等于服务端停止执行。
- **收藏同步与刷新**：定义用户隔离、保存、删除、版本迁移、来源追溯及显式刷新。刷新需要重新鉴权并获取新数据，不静默覆盖历史快照。
- **快照敏感字段语义**：前端当前只允许已知卡片结构，并按规则遮盖部分号码与引用，不能自动识别所有姓名和自由文本中的敏感信息。建议后端为可保存的字段提供数据分类、脱敏值和保存策略；验收覆盖姓名、联系方式、自由文本和未知字段，不把前端正则替换当作完整脱敏。
- **审计筛选与分页**：补充会话、动作过滤及分页完整性语义。当前前端只能对已加载记录本地筛选，不应称其为全量筛选。
- **长会话历史分页**：当前会话历史接口没有前端可用的分页契约，长对话只能一次性读取。建议提供稳定消息顺序、向更早记录翻页的游标、是否还有更多记录，以及删除／并发新增时的行为；服务端继续校验用户对会话的访问权限。前端加载旧消息时保持当前阅读锚点，失败保留已加载内容。验收覆盖空页、重复／缺失消息、会话切换时迟到的分页结果和长会话重新进入；这是后续建议，不代表当前接口已支持。

## 前端独立推进原则

后端缺口不阻塞页面结构、状态、受控组件和合成数据下的交互验证。真实接口失败时不得自动切换为样例数据；本地静态收藏不包含凭证或可重放的业务操作。真实接口、隔离样例和真实模型验证应分别记录结果。
