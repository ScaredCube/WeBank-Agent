# T-206 当前模拟业务的事务与幂等规范

最后更新：2026-10-29。当前批次覆盖转账、卡片挂失、理财申购/赎回、取消订阅；不修改前端、不连接真实银行。T-206 保留进行中：跨 HTTP 的聊天消息去重、统一执行调度器及其他数据库适配不在本批。

## 事务边界

四类业务的准备、执行共用 `services/operation_service.py` 的 `begin_write`，在任何业务读取前取得 SQLite `BEGIN IMMEDIATE` 写锁。实体归属、状态、授权、引用重查、业务更新、流水、动作状态、准备回执和成功审计在同一事务提交；异常退出 Session 时回滚。失败审计在回滚后另开事务记录；数据库不可用时不能保证失败审计落库，但不得报告业务成功。

业务规则仍留在各服务：转账重查余额、卡状态和日累计风险；理财重查账户、产品、持仓及对应申购/赎回动作类型；挂失重查卡和账户；取消订阅重查订阅归属、状态和黄色确认。红色操作仍只使用 DEBUG 模拟验证。

成功执行后动作状态统一为 `completed`。已完成执行请求返回原结果，不重复扣款、挂失或取消；重试结果代表原操作，不代表最新实时余额。

## 准备请求身份

- 转账、理财继续使用原请求体中的必填 `idempotency_key`。
- 挂失 `POST /api/cards/{card_id}/loss/prepare` 和取消订阅 `POST /api/subscriptions/{subscription_id}/cancel/prepare` 新增可选请求体：`{"idempotency_key":"client-operation-0001"}`。
- 编号为 16–64 位字母、数字、下划线或短横线。调用方为一次明确的操作生成编号，在网络重试时复用；新的用户操作用新编号。
- 挂失/取消订阅按用户、操作类型、编号去重。同键同实体返回原 `action_id`，`confirmation_token` 为 null；同键不同实体返回 400；非法编号为 422。重试与首次创建在同一写锁下判定，并有唯一约束兜底。
- 保留旧的无请求体调用；不传编号视为新申请，不承诺准备去重。相同实体的多个不同申请仍只有第一个执行成功。
- 已过期/取消/完成的申请不会因重试得到新授权或延长有效期。令牌仅首次交付，不保存明文、不支持重新取回。首次响应丢失时，客户端应查原动作，并在适用时取消或等待过期后明确重新发起。
- 挂失响应的 `confirmation_token` 从字符串扩展为可空，旧调用的首次成功响应保持字符串；订阅原本已支持可空。

## Agent 准备

准备工具从服务端 `request_context` 和业务类型派生稳定编号，不再每次调用随机生成。一次服务端请求内，同业务重复准备不会重复建单，改变参数也不能绕过已有请求的冲突检查；模型不能指定幂等编号。重试没有新令牌，Tool 返回固定不可用提示，不发出可再次授权的动作事件。

这是请求内防重：新的 HTTP 聊天请求有新的服务端请求 ID，**用户重复发送消息或重新提交整条 HTTP 请求仍可能生成新申请**。本批没有增加客户端聊天消息 ID、消息去重或确认事件恢复；不要将此能力描述为端到端恰好一次处理。直接调用 Tool 且没有服务端请求上下文时使用随机编号，调用者需自行提供请求边界。

## 新表与引用重查

新增 `OperationPreparation` 表：用户、操作类型、幂等编号、实体 ID、动作 ID、数据引用行 ID、原请求范围。唯一约束为 `(user_id, operation, idempotency_key)`，动作 ID 也唯一。不保存手机号、卡号明文、确认令牌或模型原文。

挂失绑定准备时的账户引用，取消订阅绑定准备时的订阅引用。执行在同一事务重查原绑定，引用被吊销、删除、过期、归属/类型/实体不一致时拒绝；重新创建引用不能恢复旧申请的授权。转账和理财继续使用已有绑定表/字段。

启动通过 `create_all` 增加新表，不修改旧表结构，不要求删库。**升级前未完成的挂失/取消订阅缺少绑定，必须重新准备**；已完成请求仍走原结果重试。本次开发不修改用户已有数据库，也不追补缺失绑定。

审计新增 `operation_prepare_retried`，只关联用户、动作和请求，不记录客户端编号。原有业务成功/失败及引用拒绝事件继续使用。
