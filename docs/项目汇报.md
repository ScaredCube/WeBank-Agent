## 2026-11-02 前端关键动效回补

按用户确认，在 `T-UX-422` 的静态基线上恢复“有明确目的”的关键交互动效，不做全站动画化；业务、SSE、风控、令牌化、确认与执行链路未改动。

- **动效语言**：新增 `frontend/src/lib/motion.ts`，统一 `DURATION`、`EASE_OUT`、`EASE_IN_OUT`、`EASE_DRAWER`、`EASE_CELEBRATE`、`SPRING_SOFT`、`SPRING_LIFT` 与 `useMotionReduced`。UI 动效控制在 120–320ms，主题揭幕 460ms；优先 `transform/opacity`。
- **浮层**：右侧工具抽屉与手机资产页改为 `motion` + `AnimatePresence`：遮罩 200ms fade，面板 320ms 从右/左侧进入，退出 220ms；桌面资产栏保持普通静态列，不对宽度做动画，避免布局回流。焦点返回与 Escape 行为保持不变。
- **弹窗**：`DialogContent` 继续使用 Radix，外壳采用 `data-state` + CSS 进退场（遮罩 180ms，内容 220ms opacity + scale 0.96→1，退出 160ms），避免与 Radix Presence 的卸载时机冲突。
- **动作流程**：步骤圆点/连线颜色过渡 160–200ms，完成对勾 `scale(0.6→1)` 180ms；状态文案按 keyed fade 160ms；操作完成时企鹅 `scale(0.92→1)` + fade 420ms，仅播放一次。未改变确认、模拟验证、执行和状态查询逻辑。
- **拖拽**：浮层激活 140ms 抬升；源卡 `scale(0.985)/opacity 0.9`；目标卡呼吸描边 1.6s；放下后 240ms settle；取消/松手通过 CSS 过渡回位。减少动态效果时仅保留现有边框高亮。
- **输入区**：意图胶囊采用高度 0→auto + fade 180ms；引用芯片 pop 140ms；`@` 对象下拉 `scale(0.98→1)+fade` 160ms；拖放遮罩 120ms fade。
- **消息与结果**：仅新增消息（不在历史回读中重复）做 160ms `opacity + y(4px→0)`；可信结果卡/完成卡 220ms 入场；流式文本与光标保持原样，未做逐 token 动画。
- **隐私与按压**：金额隐藏/显示使用 160ms blur/opacity 过渡；主按钮、首页常用事务和 `Button` 统一 120ms `scale(0.985)` 按压反馈；不做数据表格/图表数字滚动。
- **主题**：恢复 `startViewTransition` + `flushSync` 的圆形揭幕，时长缩短为 460ms，圆心取主题按钮右下角；快速连点时忽略后续过渡，减少动态效果时同步切换。新增 `::view-transition-*` 样式；`ThemeProvider.test.tsx` 覆盖支持过渡和减少动效两条路径。
- **吉祥物**：登录/首页 `MascotStage` 仅做 8s 轻微上下浮动（≤2.5px、≤0.6deg），不做鼠标跟随或视差。
- **验证**：`npm run test` 32 个文件 / **207 passed**；`npm run lint` 0 errors（7 条既有 warning）；`npm run build` 通过（保留 >500kB chunk 警告）；Playwright（Chrome，本地 5199）**3 passed**，覆盖手机资产胶囊、桌面隐私、桌面左右布局与抽屉分段切换。未做真实设备手感、真实后端连续联调和真实模型下的动效验收。
- **限制**：动效只在浏览器与 jsdom 行为层验证，未做真实手机帧率、软键盘、低端设备与 `prefers-reduced-motion` 真机验收；`motion` 使主包体积保持在 536.91 kB（构建警告），后续可考虑按路由拆分。

- **拖拽**：新增 Pointer Events 拖拽引擎，触摸长按 250 ms、9 px 滚动容差、鼠标 5 px 激活、浮层跟随、目标命中高亮、边缘自动滚动、Esc / pointercancel 取消、减少动效支持；同时保留点击选源再点目标以及键盘 Enter / Space 的替代路径。
- **碰撞矩阵**：银行卡→银行卡内部转账、银行卡→联系人对外转账、联系人→银行卡收款、银行卡→持仓申购、持仓→银行卡赎回、持仓→持仓转换；未定义组合只提示，不调用 AI。
- **意图胶囊**：碰撞后回到对话，输入框上方出现“动作 · 来源 → 目标”，带示例金额/备注回填；发送时前端只提交 `intent` 的动作、来源实体 ID、目标实体 ID，不提交标签或 token。
- **前置提示词**：`ChatRequest.intent` 由服务端 `intent_service` 重新校验归属与状态，生成 `<CARD_...>` / `<CONTACT_...>` / `<PRODUCT_...>` 引用。**token 化提示词放在当轮用户原文之前注入模型**；同时把用户可见的 `【前置意图】转账 · 工资卡 → 张三` 胶囊行持久化到该条用户消息顶部。界面在用户气泡上方渲染胶囊，历史回读后仍可见；token 正文不写入历史。模型金额必须与用户原文一致，来源/目标 token 由服务端覆盖，模型不能替换。
- **对话轮空修复**：Tool-only 的 `action_required` 轮次现在持久化一条助手占位消息（“已生成待确认操作…”）；固定弹窗执行完成后，当前页面追加服务端确认的完成结果卡。刷新后完成卡以操作记录为准。
- **第二轮意图修复**：内部转账黄色动作的 `action` 含 `datetime`，此前直接放入 SSE 导致 `json.dumps` 异常，前端只能看到“工具不可用”或无弹窗；现统一经 `PendingActionResponse.model_dump(mode="json")` 序列化。绿色内部转账的 Tool 摘要也增加固定渲染，不再返回“工具不可用”。`AgentLoop` 在本轮带前置意图时追加服务端 system 指令，要求调用对应工具且不得要求重新选择账户/联系人。
- **模拟验证后自动执行**：红色动作在验证码校验通过后直接调用原执行接口，不再要求用户额外点击“执行操作”；验证失败仍停留在验证码输入，通道异常则进入“结果不确定”，需查询服务端状态。黄色动作仍需确认后单独执行。

## 3. 系统架构

```
浏览器
  │  React 19 + Vite（登录 / 对话 / 确认弹窗）
  │  fetch + SSE 解析
  ▼
Vite dev proxy  /api ──────────────► FastAPI
                                       │
                        ┌──────────────┼───────────────┐
                        ▼              ▼               ▼
                   api/routes     agent/loop       db/services
                   auth/chat      LLM adapter      SQLModel + SQLite
                        │              │
                        │              ├─ MockProvider（离线）
                        │              └─ OpenAIProvider（OpenAI 兼容）
                        ▼
                  services/chat_service（会话与消息事务）
```

设计边界：

- 路由只做鉴权、参数校验与编排，不直接调用模型客户端。
- 所有模型调用经过 `backend/app/agent/llm.py`。
- AgentLoop 注册 9 个绿色只读 Tool（余额、交易、月度账单、卡片状态、理财、订阅）、受限计算器 `calculate`，以及对外转账／内部转账／收款／取消订阅等准备 Tool 和挂失／理财申购／赎回／持仓转换等红色 Tool；按服务端登录用户执行，不信任模型提供的用户 ID。
- 每次工具执行前经过独立子 Agent 护栏；护栏只接收服务端行为摘要，拒绝或异常时把固定代码风险提升一档，不直接拦截。
- 工具执行循环有次数限制；除符合固定规则的绿色内部转账外，Agent 只产生待确认或待模拟验证动作，不直接扣款。

### 4.7 模拟小额转账（T-104，已完成模拟闭环）

- `POST /api/transfers/prepare` 根据登录用户、账户余额、金额和服务端日累计判断风险；黄色动作等待确认，红色动作仅在 `DEBUG=true` 下允许创建并等待模拟验证，`DEBUG=false` 时拒绝红色操作。
- `POST /api/actions/{id}/confirm` 只记录确认；`POST /api/transfers/{id}/execute` 再次验证确认有效期、余额及风险，在 SQLite `BEGIN IMMEDIATE` 事务中扣款并生成交易记录。
- 同用户幂等键唯一；重复准备不会返回令牌明文，重复执行返回原流水。并发不同转账在锁内重新计算累计，防止绕过日累计限额。
- 收款人是模拟外部对象，不连接真实银行或真实收款账户。手机号保存认证密文、独立密钥 HMAC 和脱敏值，不写入流水；确认令牌丢失后无法恢复，需取消或等待过期并使用新幂等键。
- Agent 的 `prepare_transfer` Tool 只创建待确认动作；`action_required` 事件把令牌直接交给客户端，令牌不返回模型或写入会话历史。测试覆盖伪造用户 ID、模型伪造成功和聊天文本“确认”不能扣款。
- 仅支持 SQLite，真实多因素验证未实现；旧请求的手机号幂等摘要采用此前的密钥，升级后不保证准备重放。前端已消费确认事件，但确认令牌只发送一次，断线或事件丢失仍可能导致无法恢复，可取消未过期的待处理动作或等待过期。

### 4.8 模拟强验证基础（T-105，演示级）

- 仅 `DEBUG=true` 时可为红色模拟转账启动验证，依靠登录用户、动作和一次性令牌绑定；固定测试码通过 `DEMO_VERIFICATION_CODE` 配置，默认 `123456`，绝不是实际短信或生产多因素验证。
- 每个动作最多一个验证会话；重复启动不会重置失败次数，验证码三次错误锁定，有效期不超过动作有效期和 5 分钟。SQLite 写锁保证并发检查与失败次数更新原子性。
- 仅存验证码 HMAC 摘要，不存或记录明文；成功后状态变为 `verified`，不会执行动作。黄色确认接口不能处理红色动作，取消或过期后验证不可用。
- `DEBUG=false` 禁用整个模拟验证流程并拒绝红色模拟转账。`DEBUG=true` 时验证成功后可独立调用执行接口，执行时重新检查动作与验证有效期、余额及风险；红色动作不会降级为只需普通确认。前端模拟验证界面已接入，真实短信及生产多因素验证未实现，失败锁定目前按动作而非用户累计。
- 2026-11-01 两级红色：`details.verification` 为 `password` 时需要验证码；为 `password_face` 时验证码通过后仍需 `verification/face` 模拟人脸，人脸通过后才允许执行。最严仅到密码+模拟人脸，不调用真实人脸接口。

- 已知限制：仅按用户计数，不做 IP / 设备或登录失败限流；SQLite 下用 `BEGIN IMMEDIATE` 串行化计数；固定窗口限流存在边界突刺；手动解锁码不是生产安全机制。详见 `docs/T-203熔断限流说明.md`。

### 4.15 模拟理财（T-303，前后端已接线）

- 新增 `app/services/wealth_service.py` 与 `app/tools/wealth_tools.py`；产品、持仓和风险测评查询为绿色，申购与赎回为红色。
- 银行数据只读接口统一为 `/api/bank/wealth/products`、`/api/bank/wealth/holdings`、`/api/bank/wealth/risk-profile`，供前端负一屏和服务层封装使用，不注册为 Agent Tool；Agent 业务操作为 `/api/wealth/risk/assess`、`/api/wealth/subscribe/prepare`、`/api/wealth/redeem/prepare`、`/api/wealth/orders/{order_id}/execute`。
- Tool 直接调用 `wealth_service`，不经过 HTTP 数据接口；模型只接触产品/账户引用和金额，不接触数据接口、真实号码或卡号。
- 申购/赎回复用 `PendingAction`、一次性令牌和模拟验证；执行在 SQLite `BEGIN IMMEDIATE` 内重查账户、卡片、持仓、产品状态和验证有效期，审计失败时整体回滚。
- 同一用户幂等键唯一；重复准备不返回令牌，重复执行返回首次结果；挂失卡片阻止申购，不阻止赎回入账。
- 风险测评为 3 题固定演示问卷，服务端求和映射 R1–R4；产品收益、持仓和昨日收益均为模拟数据，不构成投资建议。
- 详见 `docs/T-303理财接口说明.md`。

### 4.16 银行数据只读接口（T-306，前后端已接线）

- 新增 `Contact` 表与 `app/services/bank_data_service.py`；启动时为演示用户幂等创建 2 个虚构联系人，只保存脱敏手机号。
- 新增 `/api/bank/accounts`、`/api/bank/contacts`、`/api/bank/dashboard` 三个只读接口，聚合账户、联系人、理财持仓和风险测评；沿用 `/api/bank/wealth/*`。
- 接口按登录用户隔离，其他用户返回空数据；不返回任何令牌、卡号明文或手机号明文；不提供联系人新增、编辑、删除接口。
- 多账户接口按任意数量账户设计，`can_transfer` 由账户状态、币种和卡片状态固定计算；默认演示种子仍为单账户，避免改变现有单账户工具回退逻辑。
- 这些接口不注册为 Agent Tool，LLM 不能直接调用；前端资产工作面已消费这些只读数据，并生成经服务端校验的 typed references。
- 详见 `docs/T-306银行数据接口说明.md`。

### 4.17 模拟订阅 / 代扣（T-304，前后端已接线）

- 新增 `Subscription`、`SubscriptionCancelRequest` 表与 `app/services/subscription_service.py`；启动时为演示用户幂等创建 2 个模拟订阅，不改变余额或流水。
- 只读接口 `/api/bank/subscriptions` 和 `/api/bank/subscriptions/candidates` 供前端负一屏使用，不注册为 Agent Tool；Agent 操作为 `/api/subscriptions/{subscription_id}/cancel/prepare` 和 `/api/subscriptions/cancel/{action_id}/execute`。
- 订阅取消为固定黄色操作：准备只创建待确认动作，确认后仍需单独执行；不做夜间升级为红色，因为它是非资金类停止操作。
- `get_subscriptions` 返回下次扣费日期、剩余天数和 7 天内续费提醒；`detect_subscriptions` 从最近 6 个月模拟支出中按同商户同金额、跨自然月出现至少 2 次识别候选，仅提示，不自动取消。
- 令牌、状态变更和审计在同一事务内；审计失败回滚；重复执行返回首次结果，多个待确认动作只有第一个成功执行。
- 详见 `docs/T-304订阅接口说明.md`。

SSE 事件格式（`data` 为 JSON）：

```json
{"type": "delta", "text": "..."}
{"type": "done", "message": {"id": 1, "role": "assistant", "content": "..."}}
{"type": "error", "message": "中文错误提示"}
{"type": "action_required", "tool_calls": [], "action": {"id": 1}, "transfer_id": 1, "confirmation_token": "<一次性令牌>"}
{"type": "bill_result", "data": {"month": "2026-01", "...": "服务端验证后的月度账单"}}

{"type": "operation_result", "kind": "internal_transfer", "data": {"transfer_id": 1, "amount_fen": 50000, "status": "completed"}}
{"type": "action_warning", "message": "此请求已创建待确认操作，确认令牌不会重新发送。"}
```

`bill_result` 只由成功的绿色 `get_monthly_bill` Tool 产生，`card_result` 只由成功的 `get_card_status` Tool 产生；模型自由文本不能制造这两类事件。`action_warning` 用于同一 `request_id` 重试时提示已有待确认动作，不会重新下发确认令牌。

### ChatSubmission / ConversationSelection / MessageResult（2026-11-01）

- `ChatSubmission`：`id`、`user_id`、`conversation_id`、`request_id`、`payload_digest`、`state`、`user_message_id`、`assistant_message_id`、`pending_action_id`、创建 / 更新时间。`(user_id, request_id)` 唯一，用于同一客户端请求的 SSE 重试去重；只保存请求指纹和关联 ID，不保存原文或确认令牌。
- `ConversationSelection`：`conversation_id` 主键、`user_id`、`account_id`、可选 `card_id`、`updated_at`。只作为同一会话内只读追问的连续性提示，不构成支付授权；每次使用都重新校验归属和状态。
- `MessageResult`：`id`、`message_id`（唯一）、`kind`、`ciphertext`、`key_version`、`created_at`。保存服务端生成的可信账单／银行卡结果加密快照，历史回读时解密并做 Schema 校验；解密失败只降级该条结果，不影响消息正文。

### Card / CardLossRequest（模拟）

- `Card`：`id`、`account_id`（唯一）、`status`、`updated_at`；每个模拟账户最多一张卡。
- `CardLossRequest`：`id`、`user_id`、`card_id`、`action_id`（唯一）、`status`。

### InternalTransfer / CollectionRequest / WealthConversion（2026-11-01 模拟）

- `InternalTransfer`：`id`、`user_id`、`source_account_id`、`target_account_id`、可选 `action_id`（黄色）、`idempotency_key`、`amount_fen`、`note`、`status`、来源/目标 `DataToken`、`transaction_id`、完成时间。绿色路径直接执行并写双侧流水；黄色路径创建待确认动作。
- `CollectionRequest`：`id`、`user_id`、`contact_id`、`account_id`、`action_id`、`idempotency_key`、`amount_fen`、`note`、`status`、联系人与账户 token、完成时间。仅记录模拟收款请求，不改变余额。
- `WealthConversion`：`id`、`user_id`、来源/目标 `product_id`、`action_id`、`idempotency_key`、`amount_fen`、`note`、`status`、来源/目标 token、完成时间。红色验证后仅调整持仓金额。
- `Card` 列表新增 `account_id` 字段，资产页可把账户卡面与挂失入口准确对应。

### ChatIntent（请求字段，非表）

- `ChatRequest.intent` 可选，包含 `action`（六种动作）、`source.kind/id`、`target.kind/id`；不包含标签、token 或金额。服务端 `intent_service` 校验归属和状态后生成提示词，见 `docs/前端接口需求.md`。

> 启动时的数据库门禁：空库允许自动初始化；已有业务表的 SQLite 必须先通过 `backend/scripts/check_chat_schema.py` 预检三张增量聊天表及关键唯一约束，缺表或结构漂移会拒绝启动。`--apply` 会先生成同目录 `.bak` 备份再补建缺少的目标表。这不是通用 Alembic 迁移，也不覆盖其他业务表字段演进或 PostgreSQL。

### Account 与 Transaction（模拟）

- `Account`：`id`、`user_id`、`name`、`masked_number`、`currency`、`balance_fen`、`status`、创建 / 更新时间。
- `Transaction`：`id`、`account_id`、唯一 `reference`、`direction`、`amount_fen`、`balance_after_fen`、`counterparty`、`category`、`note`、`occurred_at`。
- 金额单位为分；账户归属由查询服务根据服务端用户 ID 校验。

### PendingAction

- `id`、`user_id`、`action_type`、`details_json`、`risk_level`、`status`、`token_hash`、`created_at`、`expires_at`、`confirmed_at`。
- 令牌明文仅在模拟业务首次准备时通过 API / SSE 返回给客户端；动作详情不返回令牌。前端已通过固定确认／验证界面展示动作概要，但不会展示令牌正文。

### TransferRequest（模拟）

- `id`、`user_id`、`account_id`、`action_id`、`idempotency_key`、`recipient_name`、`recipient_phone_masked`、`recipient_phone_digest`、`amount_fen`、`note`、`status`、`transaction_id`、`created_at`、`completed_at`。
- 每个用户的幂等键唯一；`completed_at` 用于计算北京时间当日已完成转账累计。

### VerificationSession（仅演示）

- `id`、`action_id`、`user_id`、`code_digest`、`attempts`、`status`、`created_at`、`expires_at`、`verified_at`；每个动作最多一个会话，验证码明文不入库。

### AuditLog

- `id`、`user_id`、`request_id`、可空 `conversation_id` / `action_id` / `transfer_id` / `transaction_id`、`event_type`、可空 `tool` / `risk_level` / `reason_codes` / `result`、`created_at`。
- 字段、事件、工具名、状态与原因代码受白名单约束；不保存用户输入摘要、参数、身份凭证或敏感数据。详细事件、事务和 T-207 预留见 `docs/T-201审计说明.md`。
- 扣款、流水与成功审计同事务；拒绝 / 回滚后的失败记录在独立事务写入。审计库不可用时不能保证失败记录持久化，但不会无审计地报告成功。

### Contact（模拟）

- `id`、`user_id`、`name`、`bank_name`、`masked_phone`、`status`、创建 / 更新时间。
- 只读演示数据，不保存手机号明文；不提供新增、编辑、删除接口。

### Subscription / SubscriptionCancelRequest（模拟）

- `Subscription`：`id`、`user_id`、商户、金额（分）、周期、下次扣费日期、状态、创建 / 更新时间。
- `SubscriptionCancelRequest`：`id`、`user_id`、`subscription_id`、`action_id`（唯一）、状态。
- 订阅为只读模拟数据；取消只改变订阅状态，不扣款、不产生流水。

### OperationPreparation（T-206）

- `id`、`user_id`、`operation`、`idempotency_key`、`entity_id`、`action_id`、`reference_id`、`request_scope`。
- 用户/业务/编号联合唯一，动作 ID 唯一；挂失及取消订阅的准备回执与原始引用绑定，和动作、成功审计一起提交。不保存确认令牌明文。
- 新表由 `create_all` 增量创建；旧未完成挂失/订阅取消申请缺少绑定，执行时安全拒绝，需重新准备；已完成执行重试保留。

### WealthProduct / WealthHolding / WealthOrder / WealthRiskProfile（模拟）

- `WealthProduct`：`id`、名称（唯一）、类别、风险等级、参考年化基点、期限、起购金额（分）、状态。
- `WealthHolding`：`id`、`user_id`、`product_id`、持仓金额（分）、昨日收益（分）、状态；同一用户同一产品一条记录。
- `WealthOrder`：`id`、`user_id`、`account_id`、`product_id`、可选 `holding_id`、`action_id`（唯一）、`idempotency_key`、`order_type`、金额、备注、状态、交易 ID、执行后余额与持仓、账户/产品引用 ID、请求范围和时间；用户幂等键唯一。
- `WealthRiskProfile`：`user_id` 主键、风险等级、测评分数、测评时间；固定 3 题演示问卷，服务端计算。

### SecurityState

- `user_id` 主键；`failure_count`、`failure_window_started_at`、`locked_until`；`request_count`、`request_window_started_at`；`updated_at`。
- 每个用户一行，记录连续失败窗口、锁定截止时间和固定窗口限流状态；由 `create_all` 创建，无需删库。

### DataToken、TransferTokenBinding、AuditTokenContext

- `DataToken` 保存用户级不可枚举引用、类型、可选账户实体 ID、认证密文与加密密钥版本、独立 HMAC 摘要、请求范围、有效期和吊销时间；临时号码引用本身不以明文存储，但用户聊天消息按当前策略原样保存。
- `TransferTokenBinding` 保存转账对应的来源 / 可选目标引用 ID 和原始请求范围；执行事务内重查引用、账户、余额与风险。旧待执行记录无绑定，安全拒绝。
- `AuditTokenContext` 将引用事件与已验证的内部引用 ID、类型关联；拒绝事件不写未验证的 ID。模型请求、聊天历史、日志和审计的敏感信息边界及配置见 T-207 文档。

## 7. 安全设计现状

已落地：

- AI 不接触银行业务 API；只读模拟 Tool 经服务端执行并按当前用户隔离。
- JWT 鉴权，会话与消息接口均校验归属关系。
- 密码使用 Argon2 哈希，错误提示不区分账号不存在与密码错误。
- 系统提示词明确禁止编造账户、交易与金额，并拒绝越权请求。
- 前端确认弹窗为固定组件，AI 无法生成或绕过。
- 密钥、数据库、构建产物已加入 `.gitignore`。

## 9. 已知限制与风险

1. **业务能力有限**：模拟余额、交易、月度账单、卡片查询、理财、订阅及转账 / 挂失 / 理财 / 订阅准备已接入 AgentLoop 和前端固定动作界面；真实银行、真实强验证、年度账单和其他卡片功能未接入。
2. **对话体验受限**：Mock 不调用工具；无 Tool 结果时仅允许受控自然语言，个人金融事实和操作状态必须来自服务端 Tool 或明确说明未核实；模型回复按轮缓冲，不再实时逐字显示。
3. **确认链路为模拟且凭证不可恢复**：前端已消费服务端动作事件并调用确认／验证／执行接口；确认令牌只发送一次，事件丢失、刷新或换设备后不能恢复，只能取消待处理动作或等待过期。
4. **安全机制未完整**：现有模拟链路有持久化审计和工具调用前护栏；护栏依赖真实 LLM，离线 Mock 不启用，真实判定质量与延迟未验证；按用户累计的异常熔断已有演示实现，T-207 数据令牌化完整生命周期和生产级风控仍未实现，安全自评仍需补齐。
5. **单用户体系**：仅演示账号；JWT 无刷新与吊销机制，token 存于 localStorage。
6. **会话管理仍不完整**：已支持重命名、搜索、按日期分组和历史游标分页；仍无删除／归档，空会话会累积，删除与金融审计保留语义未定。
7. **迁移能力有限**：已有 SQLite 库有聊天增量表预检与显式备份升级，但不是通用迁移；其他业务表字段演进、PostgreSQL 和在线无停机升级未实现。
8. **SQLite 并发能力有限**：开发配置 `check_same_thread=False`，不适合生产。
9. **前端包体**：Chat 已按路由拆分；仍需真实网络和设备性能测量。
10. **未部署**：无 Docker、无生产环境变量加固、无 HTTPS / 反向代理配置；`debug=True`、演示账号和固定验证码仅适用于受控模拟环境。
11. **产品形态尚未完全落地**：当前为手机竖屏 Web 演示，未集成 App；负一屏碰撞矩阵、群组 AA 和通用 Generative UI 图表仍未实现。
12. **用户输入与原数据边界**：聊天界面、历史和模型上下文按原文保留用户主动输入的号码，工具结果与工具参数才使用令牌或脱敏字段；旧库原文不会因在线读取而擦除，交付脱敏副本仍需离线工具。联系人、实体自动吊销和密钥运维尚未完成，详见 T-207 文档。
13. **隐私模式不是安全边界**：计划的金额模糊只是视觉遮罩，DOM 中仍有数值；需要配合脱敏字段与读屏处理，不能替代服务端令牌化。
14. **语音输入明确不做**：当前设计不引入 ASR，避免音频外发与额外依赖；后续如恢复需单独评估隐私影响。
15. **计算器不是沙箱**：T-205 的时限是协作式截止检查，不是独立进程或强杀机制；浮点存在精度误差，货币场景应优先使用整数分和对应业务 Tool。
16. **注入检测是启发式**：T-204 依赖固定正则，存在误拦和漏拦；历史消息在模型上下文中替换为拦截标记，界面仍按原文显示，且不清除旧库磁盘内容。
17. **熔断与限流仍是演示级**：T-203 仅按用户计数，不做 IP / 设备或登录失败限流；SQLite 下用 `BEGIN IMMEDIATE` 串行化；固定窗口限流有边界突刺；手动解锁使用固定演示码，`DEBUG=false` 时禁用。
18. **理财为模拟数据**：T-303 的产品、持仓、昨日收益和风险测评均为演示数据，不构成投资建议；没有真实净值、费率、封闭期和收益结算；前端已接入模拟申购／赎回流程，仅支持 SQLite。
19. **负一屏数据仍为模拟**：T-306 的联系人、账户和持仓只读接口已实现，前端资产页已消费；默认演示用户包含两个账户和两个持仓，联系人无写接口，未接入真实银行内部数据；返回的是展示快照，不构成交易授权。
20. **订阅为模拟且识别为启发式**：T-304 的订阅、扣费日期和候选识别均为模拟数据；识别可能误报或漏报，不代表真实扣费；取消准备支持可选幂等编号，不传或使用不同编号时仍可能产生多个申请，只有第一个执行成功；未接入真实代扣。
21. **兼容边界**：升级前未完成的挂失/取消订阅没有引用绑定，须重新准备；挂失准备重试的确认令牌可为 null。聊天请求幂等已覆盖客户端 `request_id` 重试，但确认事件丢失仍无法恢复。T-206 保留进行中。
22. **无 Tool 意图分类仍是有限规则**：`response_policy` 使用中文词表、简写转账正则和输出过滤，不能证明覆盖所有混合意图、口语省略和对抗表达；R2-01 的具体复现已修复，但仍需 Agent／风控负责人独立复核。
23. **内部转账绿色路径仍需生产复核**：≤1000 元内部转账由 Tool 直接执行，依赖固定的归属、余额、卡片状态、当日累计和金额原文校验；当前仅 SQLite 模拟环境与测试覆盖，真实网络、并发和真实设备尚未验收。
24. **收藏仍是本机非加密存储**：收藏金额与来源以明文保存在 IndexedDB，退出登录后保留；当前仅可按“比赛模拟数据”范围使用，真实用户数据需服务端加密或本地加密方案。

## 2026-11-01 · 用户输入展示与工具令牌边界调整

**问题**：余额查询发送时正常，但历史回读把“演示活期账户（**** 0001）\n可用余额：5,000.00 元”显示为“（**** ****）\n可用余额：*,***.** 元”。根因是 `mask_text` 的累计位数规则把卡号尾号 4 位与金额 6 位相加达到 10 位后，替换了整段文本的全部数字；该函数又被用于助手历史回读。

**策略调整**：

- 聊天界面、消息历史和送模型上下文不再对用户输入做脱敏；用户主动输入的卡号、手机号按原文展示、保存并进入模型。

- 工具调用与工具结果仍使用令牌或脱敏字段：查询 Tool 只返回脱敏号码、实体 ID 或令牌，不向模型返回真实卡号。

- 用户本轮输入中的手机号额外生成请求级 `phone_input` 令牌，作为 `prepare_transfer.target_token` 的工具句柄；原文不被替换。
- 旧库脱敏副本仍使用 `scripts/redact_legacy_copy.py` 离线处理，在线界面不再承担遮盖职责。

**代码变化**：

- `backend/app/api/routes/chat.py`：移除 `redact_input` 调用与历史 `mask_text`；消息、标题、对象上下文按原文返回；新增手机号工具引用上下文。

- `backend/app/services/redaction.py` 的 `mask_text` 仍用于工具结果和旧库离线副本；`mask_value` 继续在 Tool 结果边界脱敏。
