# 项目汇报

> 最后更新：2026-10-27
> 当前阶段：P0 演示骨架已完成，T-101 只读 Tool 进行中

## 1. 项目概况

本项目为“银行 AI 智能体”参赛作品，目标是让用户用自然语言完成银行服务：Agent 负责理解意图与组织流程，所有真实业务动作由后端固定代码执行，并对 AI 保持零信任。

当前版本是**可运行的工程骨架（walking skeleton）**：登录、多轮对话、流式输出、会话持久化、模型切换已经可用；转账、账单、卡片、理财等业务场景与风控、审计、护栏尚未实现，仅预留了扩展接口。

## 3. 系统架构

```
浏览器
  │  React 19 + Vite（登录 / 对话 / 确认弹窗）
  │  fetch + SSE 解析
  ▼
Vite dev proxy  /api ──────────────► FastAPI
                                       │
                        ┌──────────────┼───────────────┐
                        ▼              ▼               ▼
                   api/routes     agent/loop       db/services
                   auth/chat      LLM adapter      SQLModel + SQLite
                        │              │
                        │              ├─ MockProvider（离线）
                        │              └─ OpenAIProvider（OpenAI 兼容）
                        ▼
                  services/chat_service（会话与消息事务）
```

设计边界：

- 路由只做鉴权、参数校验与编排，不直接调用模型客户端。
- 所有模型调用经过 `backend/app/agent/llm.py`。
- AgentLoop 使用只读工具注册表，按服务端登录用户执行绿色 Tool，并将结果返回模型；不信任模型提供的用户 ID。
- 工具执行循环有次数限制；黄 / 红操作、服务端确认和强验证尚未接入。

关键实现细节：

- 对话历史按最近 `LLM_MAX_HISTORY`（默认 20）条截取，避免上下文无限增长。
- 首条用户消息自动生成会话标题（截取 24 字）。
- 模型流式异常时返回中文 `error` 事件；客户端断开时尽力落库已生成内容。
- SSE 心跳 15 秒，关闭缓冲以支持代理转发。

## 5. 接口清单

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | 否 | 健康检查，返回 LLM 模式与模型名 |
| POST | `/api/auth/login` | 否 | 登录，返回 JWT 与用户信息 |
| GET | `/api/auth/me` | 是 | 当前用户 |
| GET | `/api/auth/demo-account` | 否 | 仅 debug 下返回演示账号 |
| GET | `/api/chat/conversations` | 是 | 当前用户会话列表（按更新时间倒序） |
| POST | `/api/chat/conversations` | 是 | 新建会话 |
| GET | `/api/chat/conversations/{id}/messages` | 是 | 会话历史消息 |
| POST | `/api/chat/conversations/{id}/messages` | 是 | 发送消息，SSE 返回 |

SSE 事件格式（`data` 为 JSON）：

```json
{"type": "delta", "text": "..."}
{"type": "done", "message": {"id": 1, "role": "assistant", "content": "..."}}
{"type": "error", "message": "中文错误提示"}
{"type": "action_required", "tool_calls": [...]}
```

## 6. 数据模型

### User

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | int, PK | 自增主键 |
| username | str, unique | 登录名 |
| password_hash | str | Argon2 哈希 |
| display_name | str | 展示名 |
| created_at | datetime | UTC |

### Conversation

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | int, PK | 自增主键 |
| user_id | int, FK user.id, index | 归属用户 |
| title | str | 默认“新对话”，首条消息后自动生成 |
| created_at / updated_at | datetime | UTC |

### Message

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | int, PK | 自增主键 |
| conversation_id | int, FK conversation.id, index | 归属会话 |
| role | str | user / assistant（system 预留） |
| content | str | 消息正文 |
| created_at | datetime | UTC |

> 数据库无迁移工具，表结构变更目前依赖删除 SQLite 文件重建。

### Account 与 Transaction（模拟）

- `Account`：`id`、`user_id`、`name`、`masked_number`、`currency`、`balance_fen`、`status`、创建 / 更新时间。
- `Transaction`：`id`、`account_id`、唯一 `reference`、`direction`、`amount_fen`、`balance_after_fen`、`counterparty`、`category`、`note`、`occurred_at`。
- 金额单位为分；账户归属由查询服务根据服务端用户 ID 校验。

## 7. 安全设计现状

已落地：

- AI 不接触银行业务 API；只读模拟 Tool 经服务端执行并按当前用户隔离。
- JWT 鉴权，会话与消息接口均校验归属关系。
- 密码使用 Argon2 哈希，错误提示不区分账号不存在与密码错误。
- 系统提示词明确禁止编造账户、交易与金额，并拒绝越权请求。
- 前端确认弹窗为固定组件，AI 无法生成或绕过。
- 密钥、数据库、构建产物已加入 `.gitignore`。

仅有骨架、尚未落地：

- 绿 / 黄 / 红风险分级与规则引擎。
- 服务端待确认动作表、一次性确认令牌、强验证（短信 / 人脸 / U 盾）。
- 审计日志与决策链路追踪。
- 独立会话子 Agent 的调用前安全检查。
- 异常熔断、限流、注入防御。
- 受限计算工具。
- 工具级事务与回滚。

## 9. 已知限制与风险

1. **业务能力有限**：模拟余额和交易 Tool 已接入 AgentLoop，输出由固定代码生成；真实模型已验证后端余额查询，前后端联调未做。转账、账单、卡片、理财、订阅未实现。
2. **对话体验受限**：Mock 不调用工具；无工具调用时仅显示固定提示，模型自由文本暂不展示；模型回复按轮缓冲，不再实时逐字显示。
3. **确认弹窗尚未接后端**：点击确认只显示本地演示提示，没有服务端确认。
4. **无审计与熔断**：关键操作不可追溯，安全自评报告所需证据尚不完整。
5. **单用户体系**：仅演示账号；JWT 无刷新与吊销机制，token 存于 localStorage。
6. **会话管理粗糙**：新建会话立即入库，空会话会累积；无删除、重命名、分页。
7. **无数据库迁移**：模型变更需手动删库重建。
8. **SQLite 并发能力有限**：开发配置 `check_same_thread=False`，不适合生产。
9. **前端包体**：主 chunk 约 512 kB，后续可按路由拆分。
10. **未部署**：无 Docker、无生产环境变量加固、无 HTTPS / 反向代理配置。
