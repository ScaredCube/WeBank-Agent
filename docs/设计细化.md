## 0. 范围与不做的事

- 产品形态为手机竖屏 H5 / PWA，模拟内嵌在银行 App 中；当前仍是 Web 演示，不做 App 原生集成。
- 不做 IM 接入；不做语音输入；不做通用代码执行或沙箱。
- 确认、验证、风险提示均为固定组件，永不由模型生成。
- 所有账户、联系人、理财数据均为模拟数据，不连接真实银行。
- 本文描述的是目标设计，不代表代码已具备对应能力；实现进度以 `docs/项目汇报.md` 为准。

## 1. 产品形态

主屏是 AI 对话（LUI），左划负一屏是资产与关系（GUI）：

- 负一屏包含三个抽屉：银行卡（别称、尾号、余额）、常用联系人、理财持仓（产品名、持仓、昨日收益）。
- 卡片既可直接查看，也可长按拖拽，与另一张卡片碰撞后生成“前置意图”。
- 拖拽完成后回到主屏，输入框上方出现意图胶囊，用户只需补充金额与备注。
- 全局隐私开关（小眼睛）同时作用于负一屏和主屏的结构化金额展示。
- 目标：查余额、看收益不必先对 AI 说一句话；转账等操作从“完整口述”降为“一拖 + 一句补充”。

## 2. 威胁模型与信任边界

需要保护的资产：真实卡号、手机号、账户余额、理财持仓、转账收款人信息。

不可信输入：

- 浏览器与前端请求，包括 `pre_intent`、实体 ID、会话内容。
- 用户自由文本，包括直接粘贴的卡号、手机号，以及伪装成指令的注入文本。原文可以进入模型上下文，但不能作为业务授权。
- 联系人备注、银行卡别称等用户可编辑标签。
- 模型输出，包括工具调用参数、金额、收款人、自由文本。

信任边界：

- 浏览器不可信；所有实体归属、风险等级、余额、日累计均由服务端固定代码校验。
- 模型不可信；模型只能提出工具调用意图，不能决定权限，也不能从工具结果或结构化引用中获得真实卡号；用户主动输入的内容可以进入模型上下文，但不构成授权。
- Tool 层与数据库是唯一可解析令牌、执行扣款的地方。
- 失败默认拒绝（fail-closed），异常不得降级为“直接执行”。

## 3. 数据令牌化（Data Tokenization）

### 3.1 令牌格式

- 令牌示例：`<CARD_7F3K9Q2M...>`、`<CONTACT_4H8N...>`、`<PRODUCT_2C6P...>`、`<PHONE_TMP_9X...>`。
- 随机部分使用至少 128 bit 随机数，Base32 / URL-safe 编码；**禁止使用 `<CARD_01>` 这类可枚举编号**。
- 令牌按用户隔离，跨用户不可复用；模型可见，但前端不把它当作权限凭证。
- 稳定令牌用于账户、联系人、理财持仓等持久实体；临时令牌用于用户本次输入中出现的卡号、手机号，带有效期。

### 3.2 前端传什么

负一屏拖拽后，前端**不传令牌**，只传实体引用：

```json
{
  "pre_intent": {
    "action": "transfer",
    "source": { "type": "account", "id": 1 },
    "target": { "type": "contact", "id": 7 }
  }
}
```

服务端校验实体归属后，才在内部映射为令牌并注入模型上下文。这样即使客户端伪造 ID 或令牌，也无法越权。

### 3.3 Vault 数据模型（规划）

新增 `DataToken` 表：

| 字段 | 说明 |
| --- | --- |
| id | 自增主键 |
| user_id | 归属用户 |
| token | 唯一令牌，索引 |
| kind | account / contact / product / phone_input / card_input |
| entity_id | 持久实体 ID；临时令牌为空 |
| ciphertext | 可选的加密敏感值；演示阶段可为空 |
| key_version | 加密密钥版本 |
| expires_at | 临时令牌有效期；持久令牌为空 |
| created_at / revoked_at | 创建与吊销时间 |

约束：

- 同一用户、同一实体只保留一个未吊销的稳定令牌。
- 实体删除、账户冻结或用户解绑时立即吊销令牌；执行时解析失败即中止。
- 审计只记录令牌与实体 ID，不记录密文、明文或可逆密钥。

### 3.4 现有数据模型的差距

当前 `Account` 只有 `masked_number`，没有真实卡号，因此演示阶段不存在“解密出 18 位卡号”的值。建议：

- 演示阶段：令牌绑定 `account_id` / `contact_id`，工具解析出实体后直接按实体 ID 执行，不伪造真实卡号。
- 真实银行接入：当前暂不考虑；如未来实现，在同一 Vault 接口下增加加密卡号字段，`resolve` 返回明文仅限 Tool 层使用。
- `Contact` 新增手机号密文、脱敏值、HMAC 摘要；数据来源为银行内部接口，当前版本只提供只读 API 演示，不支持新增、编辑、删除联系人。
- `WealthProduct` / `WealthHolding` 新增只读持仓数据。
- 现有 `PrepareTransferRequest` 的 `account_id`、`recipient_phone` 在实现令牌化时改为 `source_token`、`target_token`。

### 3.5 加密与密钥

- 新增独立配置 `DATA_ENCRYPTION_KEY`、`DATA_ENCRYPTION_KEY_VERSION` 与 `DATA_ENCRYPTION_PREVIOUS_KEYS`（版本到密钥的 JSON 映射），**不得复用 `JWT_SECRET`**。
- 使用 AES-GCM 或 Fernet 等带认证的加密；密文包含密钥版本，支持轮换。
- 密钥只从环境变量读取，不写入仓库、日志或前端；`.env.example` 只放占位说明。
- 查询去重使用独立 HMAC 摘要，避免为了查重而解密。
- 轮换密钥不得导致令牌失效；令牌与密文解耦。
- 轮换流程：先加入新密钥并切换 `DATA_ENCRYPTION_KEY_VERSION`，旧密钥保留在 `DATA_ENCRYPTION_PREVIOUS_KEYS`；新写入使用新版本，旧密文按自身版本解密；读取或写入时机会性重加密为当前版本。
- 旧密钥兼容期定为 30 天，或直到确认没有密文引用该版本；缺失对应版本密钥时 fail-closed，不返回错误明文。
- 演示阶段不做自动轮换；如需重置，直接删除本地演示数据库即可。令牌本身不受密钥轮换影响。

### 3.6 用户输入展示与工具令牌

当前策略：**界面与历史不做脱敏**。用户主动输入的卡号、手机号按原文展示、保存并送入模型；模型可以把这些内容当作上下文，但不能据此获得业务权限。

工具边界仍保持令牌化：

- 结构化账户／银行卡／联系人引用由服务端校验归属后生成不可枚举令牌，模型只看到令牌。
- 用户本轮输入中的手机号可额外生成请求级 `<PHONE_TMP_...>` 工具引用，供 `prepare_transfer` 的 `target_token` 使用；原文不被替换。
- 临时令牌写入 Vault，有效期默认 10 分钟，仅绑定当前用户与当前请求。
- 查询工具只返回脱敏号码、实体 ID 或令牌，不向模型返回真实卡号。
- 工具参数白名单继续拒绝包含原始长号码的字段，模型必须使用服务端提供的令牌。
- 旧库如需脱敏副本，仍使用离线副本工具，不在在线界面做遮盖。

### 3.7 解析边界

新增 `services/vault.py`，只允许 Tool 层调用：

- `resolve(user_id, token, expected_kind)` 校验归属、类型、吊销状态与有效期，返回实体引用或解密值。
- 查询类 Tool 返回 `account_token` / `contact_token` / `product_token` 与脱敏字段，不返回真实卡号；模型后续引用同一实体时使用令牌。
- 路由、Schema、Agent 提示词、SSE 事件、审计日志均不得解析令牌。
- 确认弹窗展示的账户、收款人来自服务端数据库的脱敏字段，不展示完整卡号。
- 转账执行时在 `BEGIN IMMEDIATE` 事务内解析令牌并复查余额、风险、账户状态；解析失败直接回滚。
- 异常信息不得包含令牌参数或明文，统一返回中文安全提示。

### 3.8 审计与生命周期

- 记录 `token_resolved`、`token_resolve_denied`、`token_revoked` 事件，字段仅含用户 ID、令牌、实体类型、原因、时间。
- 令牌不可用时返回与“实体不存在”一致的提示，避免枚举探测。
- 审计与日志禁止出现完整卡号、手机号、密文。

## 4. 前置意图胶囊

### 4.1 交互

- 长按卡片拖到目标卡片上松手后，回到主屏，输入框上方出现意图胶囊：
  `[动作：转账] [付款：工资卡 8899] [收款：张三] [移除]`
- 发送后，胶囊行随该轮用户消息持久化，并显示在用户气泡上方；历史回读后仍保留，token 正文不进入展示。
- 用户补充“1000 元，饭钱”，发送后由 Agent 调用 `prepare_transfer`。
- 胶囊可移除、可重新拖拽；补充说明需要多轮对话时，胶囊持续存在并随每条消息重新提交，直到取消或动作创建成功；发送、取消、切换会话后清空，不允许用户手动编辑令牌。
- 不做语音输入；输入框自动聚焦失败时给出明确的点击提示。

### 4.2 服务端上下文（2026-11-01 实现）

人工确认后的实现采用**预设提示词**，而不是完整的 `pre_intent` JSON 合同：

- 前端只提交 `ChatRequest.intent`：动作、来源实体 ID、目标实体 ID。
- `intent_service` 重新校验归属、状态和碰撞矩阵，生成用户级 token。
- 服务端把胶囊渲染为一句中文提示词，追加到本轮模型输入，例如：
  ```text
  【前置意图】用<CARD_...>给<CONTACT_...>（张三）转账
  ```
- **token 化提示词不写入历史**；用户消息顶部持久化一行用户可见的胶囊文本（如 `【前置意图】转账 · 工资卡 → 张三`），前端在该气泡上方渲染胶囊，历史回读后仍可见。
- 联系人/账户名称来自服务端数据库并做长度、控制字符、尖括号清洗；卡号、手机号只以 token 出现。
- 该方案与原“标签不进模型上下文”不同，属于人工确认后的取舍：提示词可读性更好，但标签是用户数据，不是授权凭证。

### 4.3 工具参数绑定（2026-11-01 实现）

- `AgentLoop` 只允许与 `intent.action` 对应的工具。
- 服务端把 `intent` 生成的两个 token 覆盖到工具参数，模型不能替换来源/目标。
- 金额从用户原文确定性提取；模型给出的金额必须与服务端提取值一致，否则拒绝。
- 未提供金额或存在多个金额时只追问，不创建动作。
- 绿色内部转账由 Tool 在服务端复查账户、余额、卡片状态和当日累计后直接执行；黄色仍走确认后执行；红色在模拟验证通过后自动执行（不再要求额外点击执行）。红色分两级：密码/验证码，和密码+模拟人脸；护栏升级可把红色从密码提升到密码+人脸。
- 没有 `intent` 时走现有对话流程，但 token 解析与风控规则完全相同。

### 4.4 注入防护

- 用户文本、联系人名称、卡片别称都视为不可信数据；标签不进入模型上下文。
- 系统提示词声明 `pre_intent` 是服务端校验结果，模型不得自行改写来源与目标。
- 真正生效的是 Tool 层校验，而不是提示词约束。
- 对超长、换行、控制字符、尖括号等标签做长度与字符清洗。

### 4.5 失败降级

- 模型未调用工具或调用不匹配：返回固定提示，不生成“已转账”文本。
- 令牌过期、实体被删除、余额不足、风险升级：返回固定中文错误，要求重新发起。
- 任何情况下都不由前端伪造成功状态。

## 5. 负一屏拖拽

### 5.1 结构

- 负一屏顶部为全局隐私按钮；下方三个抽屉：银行卡、常用联系人、理财持仓。
- 数据来自服务端只读接口（`T-306`），前端不编造余额、持仓、收益。
- 金额统一使用后端整数分，由前端格式化展示。

### 5.2 碰撞矩阵

| 被拖拽 → 目标 | 银行卡 B | 常用联系人 A | 理财产品甲 |
| --- | --- | --- | --- |
| 银行卡 A | 本人账户间内部转账：≤1000 元绿色，>1000 元黄色；不升级红色（含夜间） | 对外转账：按金额与时间黄 / 红 | 理财申购：红色 |
| 常用联系人 A | 发起收款：黄色 | 多选联系人后可发起群组 AA 收款：黄色 | 不支持 |
| 理财产品甲 | 赎回至银行卡：红色 | 不支持 | 基金转换 / 调仓：红色 |

补充规则：

- 内部转账仅限当前用户名下、同银行账户；服务端校验归属、余额、账户状态。跨行同名账户归集不享受该例外，按对外转账处理；当前版本不实现跨行归集。
- 内部转账按北京时间当日累计判定：当日累计不超过 1000 元为绿色，超过 1000 元或单笔超过 1000 元为黄色；**不受夜间升级规则影响，永不升级为红色**。
- 这是对赛题“大额转账 >1000 元为红色”的业务例外，仅适用于本人同名同银行账户、资金不流出本人；需在安全自评报告中明确说明依据与边界。
- 内部转账绿色也必须有审计记录，并受频率限制；不得由模型自行计算余额或风险。
- 绿色内部转账没有确认弹窗，金额必须与用户原文做确定性比对；无法确定或单位有歧义时降级为黄色确认。
- 内部转账单独计算当日累计，**不占用对外转账的 1000 元日累计额度**；对外转账日累计仍只统计对外转账。数据模型需区分内部 / 对外类型，避免两类流水混算。
- 联系人为空、持仓为 0、账户冻结等不可操作卡片置灰，不参与碰撞。
- 同一卡片拖到自身、联系人与理财之间等未定义组合，直接提示“暂不支持”，不调用 AI、不产生动作。

### 5.3 触控手势

- 长按 250 ms 激活拖拽；按下后移动超过 8–10 px 视为滚动，取消长按，避免与上下滑动冲突。
- 使用 Pointer Events；未激活前不设置 `touch-action: none`，避免破坏抽屉滚动。
- 拖拽激活反馈：卡片放大浮起、背景变暗、目标卡片呼吸描边；`navigator.vibrate(50)` 仅在支持时调用，iOS Safari 不支持时必须有不依赖震动的视觉反馈。
- 可放置目标扩大不可见命中区域，最小触控尺寸 44×44 px；拖到屏幕边缘时自动滚动。
- 取消方式：拖回起点、拖出可放置区域、按 Esc、返回手势；取消后不生成胶囊。
- 桌面端支持鼠标拖拽；键盘用户聚焦卡片后按 Enter 打开“操作菜单”，选择目标完成同样流程。
- 尊重 `prefers-reduced-motion`，关闭放大与呼吸动画，仅保留边框高亮。

### 5.4 多联系人 AA

- 不做多点同时拖拽；长按进入多选模式，逐个点选联系人形成堆叠，再将堆叠拖到银行卡。
- 多选模式下显示已选人数与清空按钮；未选择联系人时不允许生成收款意图。
- 群组 AA 收款仅发起收款请求，需黄色确认；不跟踪后续到账、催收状态，也不做资金归集。结果以 Tool 返回为准。

### 5.5 回填与输入

- 碰撞完成后负一屏平滑切回主屏，意图胶囊挂载到输入框上方。
- 尝试自动聚焦输入框；浏览器拦截时显示“点击补充金额与备注”的提示，不强制弹键盘。
- 不做语音输入，避免引入 ASR 依赖与音频外发隐私问题。
- 用户删除胶囊或切换会话时，服务端侧的本次 `pre_intent` 同时失效。

### 5.6 隐私小眼睛

- 全局状态由 React Context 管理，负一屏与主屏共用；可在会话内保持，并提供明显的“金额已隐藏”标识。
- 隐藏时，负一屏余额、昨日收益、主屏结构化工具结果、图表坐标与提示框统一模糊 `filter: blur(6px)`；点击单个金额临时显示 3 秒后恢复。
- 只对服务端结构化字段生效，不对任意模型 Markdown 做正则模糊；无法可靠识别所有金额。
- 模糊是视觉遮罩，不是安全边界：DOM 中仍有数值，读屏应使用 `aria-label="金额已隐藏"`，而不是继续朗读具体数值。
- 图表组件接收 `privacyMode` 属性；确认弹窗中的金额默认按当前隐私状态展示，但用户确认前必须能主动查看。

### 5.7 响应式

- 目标宽度 390 px 起，适配 safe-area inset；不得出现横向滚动。
- 负一屏与主屏使用横向 scroll-snap；避免依赖 iOS 屏幕左缘返回手势区域，提供可见的标签或把手进入负一屏。
- 桌面端为双栏或抽屉侧栏，鼠标拖拽与触控共用同一套意图生成逻辑。

## 7. 已确认决策与暂不考虑

### 7.1 已确认

1. 内部转账绿色阈值为 1000 元，按北京时间当日累计；当日累计或单笔超过 1000 元转黄色，不升级红色；不占用对外转账的 1000 元日累计额度。
2. 常用联系人数据来源为银行内部接口；当前版本只做只读 API 演示，不支持前端维护联系人。
3. 用户消息按原文展示和保存，不因含卡号／手机号而自动遮盖；工具调用与工具结果仍使用令牌或脱敏字段。
4. 群组 AA 收款仅发起请求，需黄色确认；不跟踪到账、催收状态，也不做资金归集。
5. 密钥轮换由运维手动执行：新增密钥并切换当前版本，旧密钥保留 30 天用于解密，读取时机会性重加密；令牌不受轮换影响，缺失旧密钥时 fail-closed。

### 7.2 暂不考虑

- 真实银行接入后，令牌到真实卡号 / 手机号的解析与调用边界。
- 语音输入。当前不引入 ASR，避免音频外发与额外依赖。

## 8. 验收要点

- 工具请求、工具结果、SSE 可信结果卡和审计日志中不出现完整卡号 / 手机号；用户主动输入的内容按原文展示和回读，不作为授权凭证。
- 伪造、跨用户、过期、已吊销令牌全部被拒绝，且错误提示不泄露实体是否存在。
- 模型工具调用与 `pre_intent` 不一致时拒绝，聊天文本“确认”不能绕过。
- 未定义碰撞组合不调用 AI、不产生动作、不显示成功状态。
- 内部转账按北京时间当日累计判定，≤1000 元绿、>1000 元黄，不占用对外额度；绿色也经过服务端归属、余额、风险与审计检查；金额无法与用户原文确定对应时降级确认。
- 联系人只读接口按用户隔离，当前版本无新增、编辑、删除入口。
- 用户消息历史按原文显示和保存；工具结果仍只返回脱敏字段或令牌。
- 群组 AA 仅发起收款请求，黄色确认；不显示到账或催收成功状态。
- 250 ms 长按与滚动不冲突；390 px 竖屏无横向滚动；键盘与读屏可用。
- 隐私模式下金额模糊，读屏不朗读具体数值，且文档明确其不是安全边界。
