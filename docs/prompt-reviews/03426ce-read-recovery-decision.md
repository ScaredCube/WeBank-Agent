## 一、Before / After：行为与 UX

| 用户/模型行为 | Before | After |
|---|---|---|
| 同一会话单轮中反复调用 `list_recent_transactions(limit=5)` | 每次再次进入 ToolExecutor，重复查询与审计；可能重复渲染同一结果 | 成功的同参只读结果仅在**本轮对话内**复用，第二次不执行查询、不重复生成结果卡，模型仍收到与其 Tool call ID 对应的可信观察 |
| 模型重复读 A，同时还要求新的只读查询 B | A 被重复执行，B 正常执行 | A 复用已验证观察；B 仍正常经过完整 Guard/ToolExecutor，完成复合目标 |
| 模型连续只提出已成功执行的相同查询 | 可能消耗剩余轮次，最终触发通用错误 | 不再无意义循环；立即告知“部分已验证、其余未核实”，并展示本轮已有的可信只读结果 |
| 第一个金融只读结果成功，第二个工具执行异常 | ToolLoop 抛统一错误；交易类结果不一定能保存为用户可见消息 | 仅对已有可信只读观察生成可保存的**部分完成**回复，不将故障原因、失败操作或模型臆测写进答案 |
| 第一个只读成功，下一轮模型服务突然失败 | 可能只显示服务不可用 | 返回已验证结果与明确的未完成提示；不泄露内部异常文本 |
| 尚无任何可信 Tool 结果 | 返回错误 | 仍返回错误，不伪造查询完成 |
| 执行或尝试过资金/操作类 Tool，随后发生异常 | 继续按现有业务边界处理 | 禁止使用“只读结果已完成”的恢复逻辑推测写操作是否成功；仍输出显式错误，由既有操作状态渠道核对 |
| 中途尝试写操作/其他不可缓存 Tool 后再查交易 | 新查询按正常执行 | 立即失效本轮旧缓存，重新查询，不拿操作前的数据冒充实时结果 |

本轮采取**限定工具白名单**，只对 `get_monthly_bill`、`get_card_status`、`list_recent_transactions`、`detect_subscriptions` 的**成功结果**做同参复用。其他工具，包括动态操作状态、余额、理财订阅状态、计算器及所有 PREPARE/WRITE Tool，保持原始查询与权限校验流程。

参数比较采用解析 JSON 后的规范化表示：键序和无意义空格不同，不改变同一查询的身份；不同月份、不同 limit 等实际参数差异不会合并。

## 二、修改依据与设计取舍

**收益**：降低无效调用和额外卡片，保护已取得的可信结果，让用户在某些后续步骤失败时仍能收到有价值的信息。维持“小We持续协助完成任务”的体验，而不假装所有目标完成。

**限制**：只对*同一轮*且明确不会自主改变状态的查询快照复用；不跨会话缓存、不默认复用可能实时变化的余额或操作状态。缓存不是绕过 ToolExecutor 的新权限，必须有同轮第一次成功执行作为来源。

**失败恢复的可信边界**：服务端只读取 ToolExecutor 已经成功返回的观察并使用既有 `render_tool_result`。未成功查询及未知操作状态一律标明尚未核实。内部失败详情不会暴露给用户。

**实现成本**：Loop 增加一个只作用于当前 Chat Turn 的小字典以及一个纯函数辅助模块；无需持久缓存、向量数据库、外部基础设施或新 Agent。

**替代设计**：将所有请求缓存或让模型根据历史自行判断是否重复，可能在账户状态变化后误用旧结果，且无法保证不会绕过金融权限；本轮没有采用。

## 三、对照验证

- **相同批次重复**：两个相同的交易 Tool calls + 一个订阅检测，`ToolExecutor` 实际只收到一次交易查询和一次订阅检测；模型的两个重复 call ID 都有 Tool 回复，最终交易明细只展示一次。
- **相同 Tool 不同参数**：两个月份分别查询并保留两个账单结果卡，证明没有错误合并。
- **重复调用无进展**：受控模型第二轮仍查询相同交易，Runtime 停止重复执行并保留部分结果。
- **异常恢复**：第二个只读工具抛内部异常、Provider 下一轮抛异常，均能完成可信部分结果回复，且不泄露异常消息；没有任何可信结果时保留显式错误。
- **写操作安全**：模拟准备操作抛错不被说成成功；试图执行非缓存类工具后再次读交易，必须重新查。测试中的写操作被明确 stub，没有真实金融资金操作。
- **更广回归**：结合交易与订阅、账单、Guard、任务补齐、ToolExecutor 与 Prompt 版本基线进行定向检查。

## 四、未决问题

- 当前仅针对明确少量只读工具的精确同参重试，尚未构建跨调用语义去重（例如别名参数、不同时间范围的包含关系）。
- 在网络真实故障、多个模型版本及高延迟环境中的体验尚需继续实测；不能仅凭固定测试宣称全部恢复路径已验收。
- 与之前的“遗漏只读目标补齐”协同运作；补齐仍只有有限机会，且不能被重复调用扩大金融操作权限。

**回退**：恢复 `03426ce` 的 Loop 工具执行分支，撤掉 `read_result_recovery.py` 和行为基线条目，重跑 `test_read_tool_recovery.py`、`test_read_goal_continuation.py` 及相应金融只读测试。
