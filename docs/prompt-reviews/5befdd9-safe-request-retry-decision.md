# 小We · 请求失败后的安全重发与状态核对审查

- **基准提交**：`5befdd9`
- **完整源码 Before / After**：[5befdd9-safe-request-retry-review.md](5befdd9-safe-request-retry-review.md)
- **变更范围**：`frontend/src/features/chat/useChatController.ts` 与其定向测试、行为基线；不修改后端执行器、金融 Tool、数据库和任何主 Prompt。
- **结论**：明确失败可在用户核对后发起全新请求；其余状态保留旧请求身份并阻止无依据的重复 POST；任何状态均不自动重发。

## 1. Before / After

用户先发送「查询最近交易流水」，发生断线，然后再次点击发送同一消息。

| 服务器实际状态 | Before | After |
|---|---|---|
| `failed`（已终结，但不保证无业务副作用） | 前端沿用原来的 `request_id`，新 POST 被后端返回 409；反复尝试仍无法推进 | 第一次重发只向 GET 状态接口核对，告知“Agent 请求失败≠模拟资金操作未发生”，解除失效 ID 并保留草稿；用户核对后**再次明确点击**才生成新 `request_id` 并执行 POST |
| `completed` | 当前已知的最终断线状态可以恢复，但重复点击仍可能走原 POST 的幂等回放 | 同一条消息的重复点击先查 GET，显示既有结果，绝不第二次调用 Agent 或 Tool |
| `action_pending` | 旧 ID 的 POST 可能回放操作状态警告 | 直接显示待确认操作存在，提示查看操作记录，绝不重新获取确认令牌 |
| `processing` | 重复 POST 返回 409 | 阻止 POST，明确提示仍在处理中，保留草稿与请求身份 |
| `interrupted` | 重复 POST 返回 409 | 阻止 POST，明确提示未确认完成，保留草稿与请求身份 |
| 状态 GET 失败 | 重复 POST 可能返回 409，也可能制造误解 | 阻止 POST，保持原请求身份，提示稍后核对 |
| 刷新页面发现 `failed` | 混入“尚未确认完成”提示并继续保存 pending 标记 | 标明服务端已确认失败，清理旧标记，提示先核对历史和操作记录；绝不自动重发 |

## 2. 为什么采用这个 UX

**核心风险**：即使服务端将 ChatSubmission 标成 `failed`，模型或下一工具出错前，低风险内部转账等业务操作可能已经执行。这时用新请求编号静默重发，可能产生第二笔操作。因此不能根据失败状态自动重试。

**选择的交互**：把“核对旧请求”和“发起新的请求”分成两个显式步骤；无论系统认为旧请求失败多明确，前端都不自动触发第二次 Agent 调用。请求状态来自带登录鉴权的 GET 接口，而不是聊天气泡或模型自然语言。

**隐私与安全**：sessionStorage 继续只保存随机 `request_id`、会话 ID、创建时间，不保存消息内容或银行卡令牌。依赖服务端校验对话归属；不能从历史内容反推出操作完成。服务端继续禁止对同一旧 ID 重新执行资金操作。

**代价**：确认失败后多一次用户点击，重发前多一次轻量状态 GET。换来可解释的二次授权边界。网络/状态服务不可用时仍需要用户等待或查看历史，产品不会伪造可安全重试的结论。

## 3. 测试与质量结论

- 前端 `useChatController.test.tsx`：已失败请求先核对并保留草稿，第三次明确发送才获得新随机 ID；完成结果不重新 POST；待确认操作绝不再返回确认令牌；processing/interrupted/状态查询异常全部拒绝重复发送。
- 刷新恢复：明确失败清除 pending 身份且提醒核对操作；处理中保持未确认状态。
- 相关 SSE 解析和浏览器持久请求标记定向回归已通过；前端 TypeScript 与 Vite 构建通过。
- 后端原有 ChatSubmission 幂等与 Prompt 行为基线测试通过。**没有**测试真实大模型引发资金操作，本轮是前端/状态协议的确定性验证。
- 本轮变更已经纳入 `chat_request_recovery` 有效行为版本校验；静态 System/Guard/Recovery Prompt SHA-256 不变。

## 4. 尚存边界与回退

- 当前组件在同一挂载会话里只维护一个待核对的请求标识；多标签页、跨设备请求和历史过期场景仍需依靠后端操作记录独立核对。
- 完整的“状态即恢复”体验还依赖服务端状态持久化与 UI 历史同步；本轮主要完成**明确重发前的安全门禁**。
- 回退只需恢复上述前端控制器及其测试、审查登记；后端数据无需迁移或撤销，既有幂等性不会受影响。
