## 二、UX / 安全判断

**用户体验目标**：网页发生网络错误时，界面提示与网络真实行为必须一致；“请求失败”和“未发生金融操作”并非同义词。浏览器测试检查实际 POST 次数和 `request_id`，不只检查提示文案。

**可重复的两类证据**：

1. **真实供应商 + 真实 FastAPI / Vite / Chrome**：调用配置的 DeepSeek，但只连接脚本创建的临时 SQLite；首次模型场景在既有卡片引用、两卡展示、刷新历史及移动端重开路径通过。初次数据库检查因旧单账户假设失败；修正为与当前种子契约一致的双账户严格核验。
2. **真实 Chrome + 截获的模拟 HTTP/SSE**：使用完全受控的网络失败和权威状态，用于稳定复现异常，不依赖真实模型的随机性。只有 `failed` 且用户经历明确的二次操作，才可以产生不同随机请求 ID；其他状态不自动触发第二条 POST。

**金融边界**：E2E 全程只读，正式银行服务与本机已存在的业务数据库均不参与；测试种子、临时 Vault/HMAC/JWT 与端口全部隔离。断线测试返回的是模拟 HTTP，并不会提交任何真实业务。断言要求账户余额完全不变，不能通过降低阈值或删除安全检查让测试转绿。

**数据保护**：不把真实 API 密钥、银行卡令牌、客户内容或屏幕截图写入版本控制。测试的 demo 登录及数据仅在临时隔离环境与模拟浏览器上下文中存在。

## 三、执行命令与结果

真实只读 E2E（必须显式允许使用已配置的模型提供商）：

```powershell
cd backend
uv run python scripts/run_competition_e2e.py --live
```

真实浏览器、模拟网络失败 E2E：先在隔离端口运行 Vite，另一终端显式选择本机已安装 Chrome：

```powershell
cd frontend
npm run dev -- --host 127.0.0.1 --port 5233 --strictPort
$env:PLAYWRIGHT_BASE_URL = 'http://127.0.0.1:5233'
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npx playwright test e2e/chat-recovery.browser.cjs --workers=1
```

验收要求：真实模型 E2E 返回 `PASS`、浏览器异常测试 5/5 通过、浏览器错误为 0、隔离数据库资金操作记录为 0；如果提供商未连接或 Chrome 缺失，应明确报告无法执行，不采用模拟结果冒充真实模型验收。

## 四、残余边界与回退

- 本轮仅验收只读主链路和请求恢复状态机；**用户实际确认弹窗、红色验证和跨设备会话恢复还没有完成真实浏览器端到端验收**。
- 真实供应商单次通过不能保证模型在所有请求中都能正确选择工具；需进一步测复合意图、工具中断和恢复。
- 测试脚本与当前种子数据结构有关：若新增第三账户或调整默认余额，应重新设计模拟数据基线，不能简单忽略新账户。
- 回退：恢复基线 runner 的断言并移除新增 Playwright 用例；但这会重新引入误报和异常恢复浏览器覆盖缺口，不推荐。
