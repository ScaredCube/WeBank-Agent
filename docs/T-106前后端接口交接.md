# T-106 前后端接口交接（后端基线 8a13d62）

本说明描述现有模拟业务契约，前端尚未接线。所有请求需登录并携带 `Authorization: Bearer <登录令牌>`；示例数据均为模拟。金额使用整数分。服务端返回的错误 `detail` 为中文，界面不应根据模型回复判定交易结果。

## 对话中的动作事件

`POST /api/chat/conversations/{conversation_id}/messages` 的 SSE `data` 为 JSON。模型成功准备转账时，事件示例如下（时间和 ID 是示例）：

```json
{"type":"action_required","tool_calls":[],"transfer_id":1,"confirmation_token":"<一次性确认令牌占位符>","action":{"id":1,"action_type":"transfer","details":{"account_id":1,"account_masked":"****8899","recipient_name":"模拟收款人","recipient_phone_masked":"138****5678","amount_fen":50000,"note":"演示","currency":"CNY"},"risk_level":"yellow","status":"pending","created_at":"2026-10-28T08:00:00Z","expires_at":"2026-10-28T08:05:00Z","confirmed_at":null}}
```

`type` 是字符串，`tool_calls` 是当前为空的数组，`transfer_id` 是整数，`confirmation_token` 是字符串；`action.id` 为整数，`action_type`、`risk_level`、`status` 为字符串；`details` 是对象，上例是当前转账字段，手机号可为 `null`；时间为 ISO 日期时间字符串，`confirmed_at` 可为 `null`。风险为 `yellow` 或 `red`；动作状态为 `pending`、`confirmed`、`verified`、`cancelled`、`expired`。事件之后仍可能收到 `done`，此时 `message` 可为 `null`；它不表示转账完成。SSE 会整体缓冲模型结果，并非实时逐字承诺。

## 接口

| 接口 | 请求 | 成功响应要点 |
| --- | --- | --- |
| `POST /api/transfers/prepare` | `account_id` 整数、`recipient_name` 字符串、可选 `recipient_phone`、`amount_fen` 整数、可选 `note`、`idempotency_key` 字符串 | `transfer_id`、`action_id` 整数；`risk_level`、`status`、`message` 字符串；`confirmation_token` 字符串或 null |
| `GET /api/actions/{action_id}` | 无请求体 | 返回上面的 `action` 对象，不返回确认令牌 |
| `POST /api/actions/{action_id}/cancel` | 无请求体 | `id`、`status: cancelled`、`message` |
| `POST /api/actions/{action_id}/confirm` | `{"token":"<一次性确认令牌占位符>"}` | `id`、`status: confirmed`、`message`；尚未执行 |
| `POST /api/actions/{action_id}/verification/start` | `{"token":"<一次性确认令牌占位符>"}` | `action_id`、`status: pending`、`message`；尚未执行 |
| `POST /api/actions/{action_id}/verification/verify` | `{"token":"<一次性确认令牌占位符>","code":"<模拟验证码>"}` | `action_id`、`status: verified`、`message`；尚未执行 |
| `POST /api/transfers/{transfer_id}/execute` | 无请求体 | `transfer_id`、`status: completed`、`transaction_id`、`balance_fen`、`message`，以该响应作为执行结果 |

直接准备示例：`{"account_id":1,"recipient_name":"模拟收款人","recipient_phone":"13812345678","amount_fen":50000,"note":"演示","idempotency_key":"demo_request_00001"}`。手机号可省略或为 null；幂等键须 16–128 位，只能包含字母、数字、下划线、短横线。请求成功首次返回令牌；同一键相同参数重试返回已有动作，但令牌为 null，变更参数则拒绝。无恢复令牌接口，若令牌丢失应重新发起新的动作，旧动作自然过期或在仍可取消时取消。

黄色：准备 → 按 `action` 展示 → 用户主动确认 → 调用执行 → 按执行接口结果展示。红色：准备 → 展示 → 开始模拟验证码 → 校验 → 调用执行 → 按执行接口结果展示。确认或验证成功**不代表扣款**。默认测试码 `123456` 仅供本地演示；`DEBUG=false` 时不支持红色模拟转账或验证，不能视为真实多因素认证。

## 边界处理

- 未登录为 401；无权访问或不存在的动作详情为 404；格式不符合 Schema 通常为 422。业务拒绝通常为 400，展示返回的 `detail`，不得推断为成功。
- 动作详情可显示 `expired`；过期、已取消、已处理或令牌无效时确认 / 验证被拒绝；取消仅对未过期且 pending 的动作有效。取消后不能执行。
- 验证错误返回 `验证码错误或已锁定`，连续三次错误锁定该动作的验证；之后须重新发起。过期或已处理的验证也会拒绝。
- 准备或执行时余额不足会被拒绝；执行前重新检查风险与余额。黄色动作若升级为红色，会返回 `风险已升级，请重新发起并完成模拟验证`，原确认不能用于扣款。
- 重复执行已完成的同一转账返回原交易与原完成时余额，不再次扣款；不要把返回余额理解成当前实时余额。重复准备必须保留同一幂等键。
- 模型准备的令牌只在该次 SSE 事件返回，不会写入对话历史或返回给模型；页面丢失事件无法恢复。应妥善保管且不要放入日志、URL、聊天记录或持久存储。

一次性确认令牌是授权确认 / 验证某个待处理动作的凭证；T-207 规划的数据引用令牌用于引用敏感数据，是另一机制，Vault 尚未实现。当前模型可能直接接收到手机号，数据令牌化与入站脱敏尚未完成。

无 `LLM_API_KEY` 时离线 Mock 只返回固定提示，不会调用银行工具、不会产生动作事件。前端可用上述 REST 模拟接口联调；端到端对话触发可使用后端测试中的可控模型替身，不能将其说成真实模型表现。不得使用真实账户或真实客户数据。
