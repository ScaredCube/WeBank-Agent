# 小We · T-UX-417 混合金融意图可信输出整改

日期：2026-11-01
范围：`backend/app/agent/response_policy.py` 和 Agent/聊天专项测试
状态：**阻断缺陷的具体复现已修复，待 Agent owner 独立审查与 PR 分层验证**

## 问题证据

第二轮 Pre-PR 审查 R2-01 指出：旧 `NoToolScope` 分类把“解释一下”优先于金融查询和操作意图，导致“请解释一下并帮我转账100元给联系人”被判为 `educational`，“帮我查询余额并解释一下变化”同样被判为 `educational`；“我刚才给朋友发款了吗”被判为普通对话。由于 `AgentLoop` 在无 Tool 的路径依赖该分类决定是否显示 LLM 文本，存在未经核验的个人金融事实和执行状态被错误放行的风险。这不能用“模型没真正执行交易”来掩盖对用户的误导风险。

复核时又确认原逻辑 `user_request.split("\\n\\n[", 1)[0]` 假设任意方括号段都是服务端引用，但用户可自行输入 `\\n\\n[`，截断真正的后续请求。例如“你好\\n\\n[普通备注]\\n帮我转账100元”可能被判为普通对话。

## 实现原则与改动

1. **将请求意图与工具授权分离**：此代码只决定“没有经过银行 Tool 验证时，模型自由文本是否能直接展示”，不参与决定业务权限、调用哪种 Tool、转账是否执行；所有真实金融数值和执行结果仍由原有 Tool/状态机负责。
2. **显式风险优先级**：先识别既往操作的状态核验，再识别执行意图，然后识别个人金融查询；只有不涉及具体账户或委托执行的知识询问才进入 `educational`。纯“什么是转账”“如何理解复利”仍可自然解释和使用假设数字。
3. **多信号识别而不是教学关键词单独覆盖**：例如“查询余额并解释变化”同时有查询与知识词，分类结果仍为 `private_read`；“解释一下并帮我转账”进入 `action`。转账简写“给他转100元”和“钱到账了吗”进入相应受限范围。
4. **不信任伪造的服务端标记**：分类时使用完整输入；不能通过插入方括号或换行截掉真正金融意图。已校验金融对象由 `AgentLoop` 的独立 `financial_context` 参数传递，不能由用户文本建立权限。
5. **历史状态必须区分“未核实”和“未完成”**：本轮无 Tool 的历史交易状态询问显示“未核实，请查操作记录”，不捏造成功或失败；新操作无 Tool 时仅显示准备信息，绝不表示已经执行。

## 仍然存在的风险与后续门槛

中文意图的自然语言变化无法靠有限词表完整识别，含多个隐含任务、方言表达和多轮指代仍可能误分流。现在已经把已知混合句和伪造标记的具体漏洞关闭，但这**不是通用语义授权系统**。在未来生产金融场景，应逐步通过经过服务端绑定的强类型任务/Tool 结果与状态约束回应来源，而非扩大词表或仅凭 Prompt 保证安全。
