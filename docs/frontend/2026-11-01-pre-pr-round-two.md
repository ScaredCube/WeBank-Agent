## 审查边界与方法

本轮主要是**静态代码与依赖架构审查**，不是重新执行全部测试，也不是全部 165 个提交版变更文件的逐行审计。实际执行：读取仓库协作规范、人工设计目标、代码及前一轮审查资料；检查关键 Agent/数据库/前端状态管理实现；计算 Git 提交依赖和改动大小；只读 `git ls-remote` 核对远端基线；对若干合成中文请求执行离线分类诊断。**未运行真实模型、未读取密钥、未写入真实/团队数据库，未修改任何正在运行的服务。**

上轮可复核验证证据：F-01～F-04 累计整改中后端曾完整回归 360 项通过，前端收藏专项 74 项通过；这些结果不是本次质量审查的替代，也不能保证待拆出的每个中间 PR 独立通过。

## B. 第二轮发现及放行要求

### R2-01 · P1 阻断 · Agent 无 Tool 分类仍会错放行混合意图

**具体代码：** `backend/app/agent/response_policy.py:classify_no_tool_request` 先检查教学词表，再检查多数金融操作与私人金融读取词表；`AgentLoop` 在没有可信 Tool 事件时用该返回范围决定是否可以展示模型自由文本。

**离线复现（本轮已执行）：**

| 用户请求 | 当前范围 | 预期性质 |
|---|---|---|
| 请解释一下并帮我转账100元给联系人 | `educational` | 操作（至少包含转账意图） |
| 帮我查询余额，并解释一下变化 | `educational` | 私人金融数据查询 |
| 我刚才给朋友发款了吗？ | `conversation` | 既往交易状态核实 |
| 什么是复利？给我举个例子 | `educational` | 通用金融知识 |
| 我之前的转账成功了吗？ | `action_status` | 既往交易状态核实 |

**影响：** 未经 Tool 的模型文字可能通过过宽的教学/普通对话门禁，在金融事实或执行状态上误导用户。现有真正资金执行仍由服务端 Tool/验证隔离，不能把错误分类等同于资金越权。但这违反产品“不能以模型自述建立个人金融事实”的可信表达目标。输出词表检测只是辅助防护。

**放行门槛：** 明确安全优先的混合意图解析或多意图受限策略；对于涉及真实账户/交易状态的请求，必须由结构化 Tool 数据决定允许展示的金融事实。补足混合意图、口语省略、工具失败、教育解释和多轮上下文等对抗样例；由 Agent 业务维护者审查 Prompt 与业务路由契约，必要时拆分 Prompt 修改为独立审阅项。

### R2-02 · P1 条件阻断 · 增量数据库门禁只核对局部结构

**具体代码：** `backend/app/db/schema_guard.py` 仅核验三张增量聊天表存在、必需字段名及两项唯一约束；`backend/app/db/session.py:init_db()` 在检查通过后仍会执行全局 `SQLModel.metadata.create_all()`。缺失的其他基础业务表、字段类型差异、外键/索引结构不一致并未被全面禁止或迁移。

**影响：** 已修复“聊天增量表被静默创建”的核心风险，但不能宣称所有非空数据库都不会改变，也不能把它当成覆盖所有表的通用迁移系统。

**放行门槛：** 对比赛 SQLite 数据库明确支持的升级版本/表集合与只读检查范围；检查当前团队要集成的 SQLite 模式，对新增表/约束执行停机、备份、升级、回滚签收。发布文档不得宣称“通用自动迁移”。如果团队要求完整严格的老库模式兼容，必须扩展迁移管理后再集成。

### R2-03 · P1 需团队显式接受 · 本地收藏非加密

**放行门槛：** 团队书面限定此次比赛 PR 仅服务合成模拟金融数据，明确设备本地数据保留/清空和演示环境边界；若接入真实个人金融数据，必须另行设计服务端用户归属及加密收藏，不应直接部署当前方案。

## C. 保留的成熟设计

- **前后端可信边界：** 经过服务器归属验证的金融对象引用、Tool 结果生成银行数据卡、不允许 LLM 自行授权交易执行。
- **风险分层：** 准备/用户确认/执行采用独立服务端状态；请求幂等、断线状态核对和恢复演练体现针对银行操作的实际工程判断。
- **UX 能力：** 对象式选择、`@` 搜索、可信结果卡、收藏来源导航和移动端交互是具有实际产品价值的纵向能力。
- **性能方向：** Keyset 分页改善首次加载成本；批量读取快照将原有助手逐条查询降为分批查询。属于确定的复杂度改善，但**不能声称已经得到延迟提升百分比**。
- **测试资产：** 存在跨进程故障、加密快照、Schema 回滚、真实模型与浏览器隔离测试。但测试覆盖范围不替代架构和团队 ownership 审查。
