# 小We · 第十六批：多轮只读对象上下文、可信账单比较与 Agent 收敛

日期：2026-11-01
分支：`feature/ip-object-workspace`（独立工作树）

## 产品问题

上一批模型已具备真实多 Tool 任务，但用户选中账户并查询账单后，刷新页面重新问“那相比上个月呢？”会失去前端引用胶囊，后端也没有明确、可校验的跨轮对象来源。真实模型在部分两轮任务中还会重复调用工具，发生 Guard 拒绝或浪费时间。

## 本批能力

### 1. 安全的会话内只读对象上下文

- 新增 `ConversationSelection` 数据表，仅记录会话、用户、明确选择过的账户/银行卡 ID；不存储授权 Token 和联系人，也不继承用户的转账授权。
- 用户本轮通过 `references` 明确选择账户或银行卡时服务端核验归属和有效状态后记录。下轮若不附引用，仅对账单、消费、银行卡状态和上月对比等明确只读请求尝试复用。
- 每次复用都重新验证账户/卡片属于当前已认证用户且有效；失效时返回 400 要求重新选择。不同会话没有共享上下文。
- 复用的账户只可提供 `get_monthly_bill` 和 `get_card_status` 的服务端受控身份；对准备转账、挂失及其他非只读 Tool 不会继承授权。
- 用户看到的历史消息不会混入隐藏的 Token，模型当轮获得的有效引用是后端短期签发并只限本次调用。
- `SQLModel.metadata.create_all` 会在新版后端启动时创建新表。接入已有正式数据库之前应规划 schema migration、备份与回滚。

### 2. 对上一账单月份的可信锚定

- 从同会话**助手消息的加密 `MessageResult` 快照**读取上一张有效账单的月份及账户脱敏尾号。
- 当用户问“上个月”且当前经核验的账户与上一账单匹配时，给模型明确指代的年月；全部金额仍需重新通过银行 Tool 查询，绝不采信模型编造。
- 若加密快照损坏、缺失、账户不同则不强行复用月份；不会从用户随意输入的数字推断可信金融结果。

### 3. 银行工具结果驱动的比较和收敛

- `financial_summary.py` 只利用同账户、同币种的两个月可信账单计算消费增加、减少或持平。
- 为避免隐私模式泄漏，普通文字仅给出月份与方向，**具体金额仍显示在具备隐私遮蔽的结果卡中**。
- `read_completion.py` 判断已满足的明确只读请求：单月账单、银行卡状态、两者联合，以及同账户两月对比。全部目标 Tool 成功后直接发出安全摘要并结束该轮，不再让模型追加不必要的工具调用。
- 多月份、额外计算或转账、挂失、理财等复杂/高风险任务不会进入提前收敛路径，继续沿原 Agent/Guard 审核。

## 真实模型与 HTTP/浏览器验收

模型：TokenDance `deepseek-v4.1-flash-1017`，只使用隔离模拟银行数据库。

- 一次原始真实两轮跟踪：成功查询 2026-01 与 2025-12，约 16.6 秒，总共 3 次 Tool，Guard 全部允许。
- 收敛修复前重复两次：约 18.1 秒与 10.9 秒，前者发生 7 次 Tool 调用及 2 次 Guard 拒绝，虽拿到结果但表现不稳定。
- 收敛修复后重复两次：约 **8.0 秒和 8.2 秒**，均为预期的 3 次 Tool、3 次 Guard 允许、0 次 Guard 拒绝，2/2 完整完成，余额未变。小样本，不能视为 SLA 或长期成功率。
- 收敛后再跑原有五场景：账单、卡片＋账单、待确认转账、缺失金额追问和恶意请求拦截，**5/5**；只有待确认操作创建 1 条 pending，未扣款。
- 独立真实后端 `127.0.0.1:8017` + Vite `127.0.0.1:5197`，Chrome 1440 与 390 分辨率测试：登录→通过 `@` 选择账户→查询 2026-01→刷新→不再附引用→追问上个月→展示两个月可信结果卡及消费方向。桌面与手机均通过，无浏览器 JS 错误、横向溢出或错误弹窗。
- 脱敏结果和截图：`远程工作空间/UX验收_2026-11-01_多轮会话连续性/`。仅保留工具计数、月份、状态和截图，不在代码或日志中输出密钥/内部令牌。
- 最终完整后端 `pytest -q`（默认风控配置）**291/291 通过**；前端 `npm run build` 通过，`npm run lint` 0 错误、1 条既有 WorkspacePanel 警告。
- 现有 `8000` 与 `5189` 服务不作替换，隔离服务验收后停止。

## 安全与回归

- 新增跨会话隔离、失效对象拒绝、刷新后只读追问、Guard 不可用 fail-closed、模型网络中断后的可信结果恢复、纯 Tool 数据比较及保守收敛的离线测试。
- 因已完成的只读 Tool 不再把敏感结果发给下一轮模型，旧隐私测试调整为验证模型只调用一次，Tool 明细不会被转发；原脱敏快照与 API 输出检查保留。
- 转账金额/联系人权限、Guard 风险判断与业务工具执行规则不变。

## 仍未解决的问题

- 多人多账户高并发、重复 POST 幂等、断网后重新发送的精确去重，尚未形成正式事务级协议。
- 会话对象关系目前优先覆盖账户、银行卡的只读查询；联系人和交易不从历史自动授权。
- 复杂多个月份比较、图表数据的跨轮合并和更广泛自然语言指代需要进一步研究。
- 当前为小样本真实模型测试与模拟银行环境，不能推定生产成功率；正式环境上线仍需权限审计、数据库迁移与安全评审。
