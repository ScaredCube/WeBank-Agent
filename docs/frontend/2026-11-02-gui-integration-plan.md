# Generative UI 集成实施计划

目标：在现有 Runtime 上完成消费分析、分类选择、可信续问与历史恢复，保持银行工具和金融操作安全边界。

架构：工具执行继续由 ToolExecutor 授权；聊天轮次收集可信结果，并在不损失结果的前提下生成和校验受控视图。视图服务负责用户隔离、加密版本和交互；前端负责聊天摘要、工作区和版本选择。技术栈沿用 FastAPI、SQLModel、React、TypeScript 和 json-render。需求以用户提供的《小We · Generative UI 集成开发任务书》及现有协议为准。

## 并行分工与验证

- 视图基础：`backend/app/models.py`、数据库预检及升级、视图 API 和服务；测试用户隔离、加密、版本冲突、重复交互及升级兼容。
- 可信数据：账单工具与 ToolExecutor 传递服务端来源信息；将视图选择解析为有界可信数据。测试数据归属、注入边界和选择摘要。
- 聊天运行时：`chat.py`、`chat_turn.py`、`chat_messages.py`、聊天 Schema 和请求幂等；接入视图上下文、生成与历史关联。测试生成失败、重复请求、断流和历史回读。
- 前端：消息与 SSE 协议、聊天工作区、视图交互和失败恢复；测试聊天、筛选、续问和刷新，保持资产及金融确认行为。
- 集成验证：依次执行定向协议测试、隔离前后端浏览器流程和真实模型验收，最后检查完整回归及交接。模型凭据和真实数据不进入代码或日志。

交互协议采用现有 `ViewEnvelope`，请求使用 `view_context: {view_id, revision}`；由服务端确认视图归属和版本。共享接口变化由主代理协调。视图生成失败必须保留可信结果；用户端的数据不能成为可信金融事实。
