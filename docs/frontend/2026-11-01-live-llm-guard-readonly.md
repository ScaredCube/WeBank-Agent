## 真实模型暴露的问题及修复

1. **供应商工具调用 ID 的误拒绝**：随机工具调用 ID 中包含会命中电话号码/账户脱敏表达式的字符组合，导致 `AgentLoop` 在 Guard 之前错误拒绝。已在 `OpenAIProvider` 完成流式分片合并后，为每个非空第三方工具调用 ID 分配随机、仅含字母的内部关联 ID。Assistant 的 tool_calls 与后续 Tool 回复复用该关联 ID；缺失 ID、非法参数仍按既有白名单拒绝。
2. **模型无法可靠复写受控引用 Token**：模型能准确选取 `get_monthly_bill` 和月份，但错误复写账号令牌，银行 Tool 正确返回「引用不可用」。已让 Chat Route 在验证用户选择的账户归属后，把受控 `account_token` 显式传给 AgentLoop。仅针对 `get_monthly_bill` 的合法只读调用，在参数白名单验证通过后以服务器核验令牌覆盖模型提供的值。未选择账户时不会自动补授权；不改变转账、挂失及高风险工具的执行逻辑。
3. 同步了 SYSTEM_PROMPT 的账单查询引用规则，指导模型只处理其负责的月份参数。

## 隔离的真实模型业务测试

- 用 `fastapi.testclient.TestClient` 走真实 FastAPI 路由、鉴权、数据库、银行 Tool、Guard、SSE 和加密历史链路，**未启动或替换现有监听服务**。该验收是进程内 ASGI HTTP 测试，不是独立端口或浏览器 E2E。
- 使用独立的临时 SQLite、模拟用户与账户、进程内随机生成的 JWT/加密/HMAC 密钥；测试模拟账单 2026-01。没有真实银行卡数据或外部金融操作。
- **最终结果**：模型选中 `get_monthly_bill` → Guard 允许 → Tool 成功 → `bill_result`、`delta`、`done` 各 1 个 → 历史 1 条助手消息 → 1 条密文金融结果快照 → 刷新查询历史 API 可恢复。
- 最后一次完整链路约 **5.22 秒**。模型仍未原样复制 Token，但服务端安全绑定使该错误不影响通过验证的账户查询。
- QA 脚本：`远程工作空间/UX验收_2026-11-01_真实模型初测/`。脚本只输出必要结果、参数字段名、校验布尔值和审核状态；不打印令牌值。

## 交付原则

继续坚持用户金融对象先由后端验证所有权、模型负责业务意图和工具选择、工具执行前 Guard/白名单双重校验、银行结果只来自可信 Tool。所有历史结果使用已有加密快照，不允许模型自行写金额或卡状态。
