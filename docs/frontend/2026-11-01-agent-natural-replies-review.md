# 小We · Agent 自然语言与 Prompt 质量审查（候选修复）

日期：2026-11-01。基础版本 `eb95e91`。对应 PR 前质量审查的一部分。

## 根因与改动理由

观察：用户输入“hi”和“我想转账”后，真实 Agent 都显示“未能通过工具完成查询或准备模拟转账”。

经源码确认：`app/agent/loop.py` 在没有 Tool Call / Tool Result 的路径直接丢弃模型累计的 `content`，并返回固定失败提示。即使供应商模型流式响应成功，用户也看不到问候或对缺失参数的追问。因此仅修改 Prompt 不足以解决症状。

本批修复：
- 增加 `app/agent/response_policy.py`：在模型无工具返回时，保留普通问候、功能介绍、信息不足追问等自然语言；输出前检查内部标识、虚构金融结果和未经验证的执行成功宣称，不能作为金融数据权威来源。
- `AgentLoop` 将模型无 Tool 情况的固定失败文案替换为上述保守呈现。Mock 的演示提示保留。成功 Tool、加密结果卡、Guard 和资金状态机路径未改变。
- 对原本属于团队的 `prompts.py` 仅作针对性最小修订：统一“小We”产品身份，明确无 Tool 的交互能力与最新 recipient_contact_token / card_id / 服务端身份绑定约定。Guard Prompt 未调整。
- 增加离线测试 `tests/test_agent_natural_replies.py`，相应更新原先依赖固定失败文案的断言。
- 扩展 `scripts/evaluate_agent_live.py` 的可选场景 greeting / transfer_clarify，保留默认执行范围和 --live 的费用授权。

## 验收

离线定向：34/34 通过。包含自然回复、会话持久化、拒绝模型虚构余额或已转账、原有 Guard 安全约束。
真实 TokenDance + 隔离模拟 SQLite + 真实 Guard：greeting、transfer_clarify、bill，3/3 通过。问候和澄清无 Tool Call；账单仍通过 1 次 Tool + Guard 获取可信数据。余额不变，无新资金操作。真实评测耗时：1.669、1.664、3.328 秒，均为小样本开发诊断，不是稳定性基准。

## 安全和质量审查的剩余风险

`response_policy.py` 是启发式输出保护，不是通用语义保证。对复杂金融语言、中文口语同义变体及提示词注入仍需要更完整的语义约束与对抗评估。不能用正则匹配替代后端权限、Tool 结果、交易确认，且不能把本批测试通过宣称为所有模型输出安全。

后续 PR 前审查建议：将 Tool-free 答复与工具意图路由契约化、完善对抗样例；收集正常解释的误拒绝率、金融幻觉漏检率和无必要 Tool Call 频率；比较版本 A/B 的自然性与拒绝边界。若评估不达标，应能独立回滚本批 Prompt 与输出策略，不改变已加密数据或已建立的交易状态。
