```markdown

- 不在本 PR 范围的已知问题：

- 部署前配置与脱敏演示限制：
- 升级步骤、备份与回滚：
- 旧版本客户端/数据库的兼容策略：

## 验收证据（区分“测试”和“工程质量”）
- 静态代码质量报告 / 需要团队接受的风险：
```

**PR 不应包含**：`.env`、真实密钥、数据库实体数据、可复用访问令牌、真实银行用户信息、测试中生成的 SQLite 或构建目录；也不必把全部批次日志复制进 PR 正文。描述应链接少量权威文档和必要的具体历史记录。

## 3. 具体审查/签收分工建议

| 角色 | 有权签收的主要内容 |
|---|---|
| 前端/UX（当前开发负责） | 信息架构、触达路径、a11y、手机交互、主题/资源、组件状态管理、前端性能 |

同一人可以兼任，但不能把代码作者的自检当成独立 reviewer 的批准。
