# 第九批 · 可信月账单结果持久化与真实浏览器联调

日期：2026-10-31
分支：`feature/ip-object-workspace`
范围：本分支专属 worktree，未推送未合并，团队主工作树不做修改。

## 用户可观察能力

1. 选择账户 → 询问月度消费 → 后端账户鉴权 → Agent 调用 `get_monthly_bill` → 展示真实工具数据卡。
2. 可信结果作为助手消息的附属快照保存；刷新、关闭重进后，从有权限的历史会话接口重新取得图表。
3. 结果卡与具体消息 ID 绑定，用户无法通过普通聊天接口提交或冒充 `bill_result`。
4. 账单数值由结果卡展示，助手只简短说明，删除通用的“结果卡片”次级标签；修复历史中长数字重复遮蔽造成的阅读噪音。
5. 隐藏金额开关继续覆盖恢复后的结果卡，旧会话没有快照时正常显示消息。

## 实现方式

- 数据表：`MessageResult`，一条助手消息最多一份本阶段 `monthly_bill` 快照，存入 `ciphertext`、`key_version`，由 SQLModel 在启动时进行**增量建表**（无现存表结构修改）。
- 加密：沿用 Vault 中的 Fernet 密钥管理与历史密钥轮换能力；结果在提交消息时加密，不存明文账单 JSON。密钥失效或快照损坏时历史消息仍能打开，结果卡不展示。
- 鉴权：`GET /chat/conversations/{id}/messages` 先经过已有 `_require_conversation`（用户和会话归属校验）后才取得该会话的消息与附属数据。响应加 `Cache-Control: no-store`。
- 数据来源：AgentLoop 仅在成功的 GREEN `get_monthly_bill` 工具调用后产生 `bill_result`；Pydantic `MonthlyBill` 验证结果；SSE `done` 与后续历史接口均附加 `bill_result` 字段。
- 前端：ChatPage 仍复用既有 `IntelligentCard` 与 `billResultCard` 数据校验。在历史消息上通过结果字段恢复卡片，流式过程依然使用现有事件渲染。没有建立平行的前端卡片数据库或客户端“可信数据写入接口”。
- 输出：月账单生成后，助手说明精简，可信数字由结构化卡片展示，保留完整原有工具返回能力供审计和其他下游逻辑使用。

## 边界与下一步

- 本阶段只保存成功的 **月度账单** 工具结果；同一回复若多次调用月账单工具，目前以最后一份为准，尚未构建多卡列表。
- 后续应正式设计数据库版本迁移与完整回退方案，避免依赖启动时自动增量建表；安全上线需覆盖密钥轮换、备份恢复与数据生命周期。
- 联系人、银行卡与理财持仓仍需要各自后端类型化引用、归属校验与工具结果合同。
- 面向比赛的生产验证还需要真实模型配置及 Guard 端到端验证；当前的 QA Provider 在隔离脚本内，未合入产品源码。
- UI 设计纪律：Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.
