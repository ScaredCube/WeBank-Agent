# T-207 数据引用与兼容说明

本批为现有模拟账户和工具参数实现数据引用。**T-207 仍为进行中**：联系人、理财持仓、完整实体生命周期和密钥轮换运维机制未实现，详见下文。当前策略已调整为：用户输入在界面和历史中原样保留，用户主动输入的号码也会进入模型；令牌只用于工具调用边界，避免工具参数和工具结果向模型暴露真实卡号。

## 安全边界

- 聊天输入不再改写：用户消息按原文生成标题、保存、展示并送模型，包括用户主动输入的卡号或手机号。用户消息历史也按原文回读，不做界面脱敏；注入检测命中时仍替换为 `[已拦截的可疑输入]`，该替换只影响模型上下文。
- 工具调用边界仍使用令牌：账户、银行卡、联系人、理财和订阅通过结构化引用生成不可枚举的 `DataToken`；`prepare_transfer` 只接受 `source_token`、`target_token`、`recipient_contact_token` 等引用，不接受 `account_id` 或 `recipient_phone`。服务端在事务内解析令牌并重查归属、状态、余额和风险。用户本轮输入中的手机号会额外生成请求级 `phone_input` 令牌，作为 `target_token` 的工具句柄，但原文不被替换。
- 查询工具不向模型或历史返回真实卡号：账户、卡状态、账单、交易、理财和订阅结果只返回脱敏号码、实体 ID 或令牌；`mask_value` 继续处理工具结果中的长号码和可疑文本。
- 临时引用使用随机字母组成的不可枚举标识，绑定用户、类型、本次服务端请求和 10 分钟有效期。账户引用绑定现有模拟账户 ID，解析时检查归属和 active 状态；不存在伪造的真实卡号。确认令牌是动作授权凭证，与数据引用完全不同。
- Vault 使用 Fernet 认证加密，密文绑定引用、用户和类型，另以独立 HMAC 密钥计算去重摘要。加密 / HMAC 密钥不得相同或复用 JWT 密钥。缺失、格式错误、版本不匹配或密文损坏时拒绝处理，不回退明文。
- 账户查询模型工具接受 `account_token`；`prepare_transfer` 模型工具接受 `source_token`、`target_token`、`recipient_name`、`amount_fen`、`note`，不接受 `account_id` 或 `recipient_phone`；未提供来源时仅在所属活跃账户唯一时由服务端选择。模型不可调用执行工具。服务端准备时在事务内解析引用；执行时依据服务端保存的绑定重新校验引用、账户、余额、风险和验证状态，失效则拒绝扣款。
- 旧库原文不会因读取时不再脱敏而自动清除；如需交付脱敏副本，仍应使用下方的离线副本工具，而不是把在线界面当作数据擦除手段。

## 密钥配置与手动轮换

`backend/.env` 或环境变量需要 `DATA_ENCRYPTION_KEY`、`DATA_HMAC_KEY`（分别为独立的 URL-safe Base64 编码 32 字节随机密钥）、`DATA_ENCRYPTION_KEY_VERSION`（如 `v1`）和 `DATA_ENCRYPTION_PREVIOUS_KEYS`（版本到密钥的 JSON 对象，初始为 `{}`）。可在本机通过 `uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` 分别生成两次；不要共享终端输出或提交 `.env`。

轮换加密密钥时，将旧版本和旧密钥加入 `DATA_ENCRYPTION_PREVIOUS_KEYS`，设置新的当前版本及密钥。旧密钥按设计至少保留 30 天，或直至确认无密文引用，取更长者；读取旧密文时会在成功事务中机会性重加密到当前版本。版本缺失即拒绝。保留期目前依赖人工管理，**没有自动检测或淘汰密钥的工具**；HMAC 密钥版本化及安全轮换也未实现，不要直接更换正在使用的 HMAC 密钥，否则已有请求的去重 / 执行校验可能失败。

## 原 REST 接口与迁移

为方便 T-106 联调，`POST /api/transfers/prepare` 的旧请求字段 `account_id`、可选 `recipient_phone` 暂时保持：它们仅进入服务端，服务端在同一事务校验账号归属，创建并解析数据引用，保存与转账的绑定，执行前重查。模型工具不能使用这些旧字段。动作事件、详情和确认 / 验证 / 取消 / 执行响应格式保持；请求参数验证错误统一为 `422 {"detail":"请求参数无效"}`，不回显输入。新转账使用独立 HMAC，旧版本创建的待执行转账没有引用绑定，升级后安全拒绝，须重新准备；旧数据的手机号幂等摘要使用了不同密钥，旧的准备请求不保证可重放。已完成转账的执行重试仍返回原结果。

新表通过现有 `create_all` 建立，不需删除数据库。当前聊天界面不再对用户输入和历史做脱敏，旧会话中的原始内容会按原文显示；如需交付脱敏副本，必须使用离线副本工具。需要升级时：先停止应用并备份原库；在 `backend` 目录执行 `uv run python -m scripts.redact_legacy_copy <原SQLite路径> <新SQLite路径>`。目标必须不存在；工具使用 SQLite 在线备份创建独立副本，再对副本中的消息、标题、账户名称、交易文本、转账备注和待确认动作详情做保守遮盖，原库不变。检查结果、保留受保护的备份后，手动将 `DATABASE_URL` 指向新副本并启动应用创建新表。若工具报错，不能启用该副本；副本可能仍含未遮盖内容，应按敏感文件保管。复制 / 替换与备份保留由使用者控制，本次未触碰用户现有数据库。

## 审计与未覆盖项

`token_resolved`、`token_resolve_denied`、`token_revoked` 为实际事件，审计仅暴露内部引用行 ID、实体类型和固定拒绝原因，不记录引用文本、明文、密文或密钥。操作失败回滚时，转账路径另行持久化拒绝事件；数据库不可用时请求失败，无法保证拒绝记录写入。

未完成：联系人 / 理财 / 真实卡实体的完整 Token 生命周期；账户冻结、删除、解绑时自动吊销及自动清理过期临时引用；面向用户的引用管理 / 吊销 API；加密旧密钥 30 天保留的自动审查、HMAC 密钥版本化与轮换、生产级密钥管理。T-208 已部分实现（账户／银行卡／联系人 typed references 与服务端绑定），完整 `pre_intent` 动作合同仍待开发；其他 P3 功能未开始。
