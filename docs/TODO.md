## P1 最小业务闭环

- [ ] **T-101 账户与交易只读 Tool**（优先级：最高）
  - 范围：`backend/app/tools/` 目录、账户 / 余额 / 交易记录查询；演示数据种子
  - 验收：LLM 只能通过 Tool 获取数字；Tool 返回结构统一；绿色风险自动执行并写审计占位
  - 依赖：T-007

- [ ] **T-102 风控引擎（固定代码分级）**（优先级：最高）
  - 范围：`backend/app/risk/`；按 Tool 元数据 + 金额 / 时间 / 日累计判定绿 / 黄 / 红
  - 验收：规则不依赖 LLM；小额转账 ≤ 1000 元为黄，> 1000 元为红；夜间等环境因子可升级等级；有单元测试覆盖边界

- [ ] **T-103 待确认动作与服务端确认**（优先级：最高）
  - 范围：`PendingAction` 表、一次性 token、`POST /api/actions/{id}/confirm`、超时失效
  - 验收：前端弹窗内容来自后端；确认必须携带服务端令牌；重复确认被拒绝；AI 文本无法代替确认

- [ ] **T-104 小额转账 Tool（黄色）**（优先级：高）
  - 范围：收款人 / 手机号 / 备注、金额校验、余额校验、事务与幂等
  - 验收：未确认不执行；失败回滚；重复请求不重复扣款；结果只来自 Tool 返回值

- [ ] **T-105 强验证模拟（红色）**（优先级：高）
  - 范围：短信验证码模拟（固定测试码）、验证会话、失败次数限制
  - 验收：大额转账 / 挂失等红色操作必须验证；验证码错误不执行；日志不记录明文验证码

- [ ] **T-106 前端动作确认与验证弹窗接线**（优先级：高）
  - 范围：消费 `action_required`，展示后端动作详情，调用确认 / 验证接口
  - 验收：不伪造成功状态；确认 / 取消 / 过期均有明确反馈；移动端可用

## P2 安全与可靠性

- [ ] **T-201 审计日志**（优先级：高）
  - 范围：`AuditLog` 表；记录用户输入摘要、意图、Tool 调用、风控判定、确认结果、执行结果、时间
  - 验收：关键操作可按会话追溯；敏感字段脱敏；提供只读查询接口

- [ ] **T-202 子 Agent 调用前护栏**（优先级：中）
  - 范围：独立会话检查 Tool 调用行为（功能、理由、历史、环境因子），不传原始用户提示词
  - 验收：可疑调用被拦截并记录；护栏故障时默认拒绝（fail-closed）；有对抗样例测试

- [ ] **T-203 异常熔断与限流**（优先级：中）
  - 范围：连续失败计数、可疑行为锁定、接口限流
  - 验收：阈值可配置；锁定期返回明确中文提示；解锁路径可审计

- [ ] **T-204 注入防御**（优先级：中）
  - 范围：输入检测、系统提示词隔离、工具参数白名单校验
  - 验收：常见越狱 / 角色覆盖 / “忽略规则”样例无法绕过风险分级

- [ ] **T-205 受限计算工具**（优先级：中）
  - 范围：基于 Python `ast` 的纯数学表达式求值，禁止属性访问、函数调用与导入
  - 验收：仅数值运算；超时与长度限制；不提供完整代码执行能力

- [ ] **T-206 Tool 事务与幂等规范**（优先级：中）
  - 范围：统一执行包装、事务边界、失败回滚、幂等键
  - 验收：并发重复请求不产生重复扣款 / 重复下单
