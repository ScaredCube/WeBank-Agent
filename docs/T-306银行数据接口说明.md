# T-306 银行数据只读接口

状态（2026-11-01 更新）：后端只读接口已实现并通过测试；前端资产页已消费账户、联系人、持仓和风险测评数据，支持长按拖拽、点击选源和目标选择生成意图胶囊，`@` 仍可用于只读引用。联系人、账户、持仓和风险测评均为模拟数据，不对接真实银行内部接口。

## 1. 接口边界

- 路径统一为 `/api/bank/*`，只提供 GET 只读查询。
- 仅供前端负一屏和服务层封装使用；**不注册为 Agent Tool**，LLM 不能直接调用这些 HTTP 接口。
- 不返回 `account_token`、`product_token`、`confirmation_token` 或任何一次性令牌。
- 不返回卡号明文、手机号明文；联系人手机号只返回脱敏值。
- 不提供联系人新增、编辑、删除接口。
- T-304 的 `/api/bank/subscriptions` 和 `/api/bank/subscriptions/candidates` 复用同一分层，只读且不注册为 Agent Tool。

## 2. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/bank/accounts` | 当前用户全部账户：`account_id`、名称、脱敏卡号、币种、整数分余额、账户状态、卡片状态、`can_transfer` |
| GET | `/api/bank/contacts` | 当前用户只读联系人：`contact_id`、名称、银行、脱敏手机号、状态、`can_transfer` |
| GET | `/api/bank/dashboard` | 负一屏聚合：账户、联系人、理财持仓、风险测评、生成时间 |
| GET | `/api/bank/wealth/products` | 可申购模拟理财产品 |
| GET | `/api/bank/wealth/holdings` | 当前用户模拟持仓 |
| GET | `/api/bank/wealth/risk-profile` | 当前用户风险测评 |

所有接口需要 Bearer 登录令牌，受用户级锁定与限流约束；成功响应带 `Cache-Control: no-store`。

## 3. 字段口径

- 金额统一为整数分。
- `can_transfer`：账户要求状态 `active`、币种 `CNY`、关联卡片状态 `active`；联系人要求状态 `active`。
- `card_status`：`active` / `lost` / `missing`。
- `status`：账户、联系人、持仓状态原样返回；未知状态不推断为可用。
- 联系人名称、银行名称和脱敏手机号经过保守遮盖后返回。
- 空数据返回空数组；未完成风险测评返回 `risk_level: "未评估"`、`score: 0`、`assessed_at: null`。

## 4. 数据与隔离

新增 `Contact` 表：`id`、`user_id`、名称、银行名称、脱敏手机号、状态、创建 / 更新时间。启动时为演示用户幂等创建 2 个虚构联系人，不保存手机号明文。

所有查询按登录用户过滤；其他用户的账户、联系人和持仓返回空数组。默认演示种子在 `DEMO_MULTI_ASSETS=true`（默认）时创建两个账户和两个持仓，便于演示卡→卡、持仓→持仓；测试环境通过 `DEMO_MULTI_ASSETS=false` 保留原单账户夹具。`/api/cards` 增加 `account_id`，便于资产卡面对应挂失入口。

- 2026-11-01 完整后端回归：414 passed；前端 204 passed；Playwright 2 passed。
- 未调用付费模型；真实银行数据联调或正式设备验收未完成。

## 6. 限制

- 联系人只读，不支持新增、编辑、删除；数据来源为模拟种子，不是真实银行内部接口。
- 默认演示用户包含两个账户和两个持仓，仍为模拟数据；关闭 `DEMO_MULTI_ASSETS` 可回到单账户夹具。
- 没有分页、缓存或实时刷新机制；资产页打开时按需查询。
- 返回的是展示快照，不构成交易授权；所有交易仍必须经过对应 Agent 业务接口、风控、确认 / 验证和审计。
